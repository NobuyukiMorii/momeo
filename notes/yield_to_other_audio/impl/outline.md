# 他のアプリの音に譲る 実装計画

`spike/yield-to-other-audio` で作った「他のアプリの音に譲る」しくみを、`main` で少しずつ作り直す。

今と変わること:

- 今は、momeo の録音中に他のアプリ（YouTube・語学教材など）の音がこもり、スピーカーから出た声も文字化してしまう
- 作り直したあとは、他のアプリが鳴っている間は聞いた音を捨て、Bluetooth イヤホンも音楽用の方式（A2DP）のまま聴ける。鳴り止めば書き留めを再開する

進め方:

- 1 step = 1 commit = 1つの目的
- お手本は常に `spike/yield-to-other-audio` のコード
- 実装中の調整で spike と違ってよい。ただし、やり残し・検討漏れは無くす
- spike で試して戻した変更（混ぜない設定で OS の中断に任せる、マイクだけ本体に指名する、背面で録音を止めて設定を替えて開き直す、記録係 `AudioSessionProbe`、空の文字化結果で「.」を消す）は通らず、最終形へ直接向かう
- 録音パイプラインの「状態の印の一覧」コメントは、印を足す step で一緒に書き足す
- 各 step は `phaseN/stepNN_名前/` に置く（計画は `plan.md`。説明資料の HTML は、頼んだときだけ作る）
- iOS は release ビルドで確かめる（`make run d=<端末> mode=release`。hot restart は使えないので、毎回入れ直す）

---

## 全体の流れ

```text
Phase 1  他のアプリの音をこもらせない
Phase 2  他のアプリの音に譲る        ← 一番大きい
Phase 3  録音の見張りを整える
Phase 4  中断を画面に出す
Phase 5  仕様書
```

---

## Phase 1 他のアプリの音をこもらせない

こもりの原因は2つある。録音のサンプリングレートが iPhone 全体の再生に効くことと、Bluetooth のマイクを使うとイヤホンが通話用の方式（HFP）になること。譲るしくみより先に、単独で直せるものを済ませる。


| step | やること |
| ---- | ------------------------------------------------------------ |
| 1    | iOS は 48kHz で録り、16kHz に落としてから渡す |
| 2    | リスニングを止めるときに、イヤホンを手放す（iOS） |


※ step 2 で iOS 側の窓口 `AudioSessionChannel` を作る。以降の step はここに問い合わせを足していく。

## Phase 2 他のアプリの音に譲る

他のアプリが鳴っているかを 0.5秒おきに確かめ、鳴っている間は書き留めない。


| step | やること |
| ---- | ------------------------------------------------------------ |
| 3    | 他のアプリが鳴っている間は、聞いた音を捨てる |
| 4    | Android で、録音がオーディオフォーカスを取らないようにする |
| 5    | Bluetooth のマイクを手放し、イヤホンを音楽用に戻す（iOS） |
| 6    | 中断の終わりを待たずに、自分で再開する（iOS） |


※ step 3 の後は、他のアプリが鳴っている間もイヤホンは通話用のまま（音はこもる）。step 5 で解消する。

※ step 5 は背面の扱いを含む。iOS は背面での設定の差し替えも録音の開き直しも拒否するので、背面では録音を止めてイヤホンごと手放し、前面に戻ったときに再開する。

## Phase 3 録音の見張りを整える

譲るしくみで増えた作り直しのきっかけに、見張りを合わせる。


| step | やること |
| ---- | ------------------------------------------------------------ |
| 7    | 中断から戻った直後に、作り直さない |
| 8    | 機器の抜き差しのあと、すぐ録音の生死を確かめる（iOS） |
