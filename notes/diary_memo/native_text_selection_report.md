# OS の文字選択を使うメモ一覧

確認日: 2026-09-26

## 実装内容

iOS は編集不可の `UITextView`、Android は選択可能な `TextView` を Flutter の画面に埋め込んでいます。

選択色、つまみ、語の判定、選択ジェスチャー、メニューの表示と操作は、それぞれの OS の部品に任せています。

選択中の面の内側への1回タップはアプリ側で扱い、文字選択を解除します。

本文を編集する機能や Flutter の `TextField` は使っていません。

ブロックをまたいで選択するため、検索結果の本文全件を、時系列順の1つのネイティブ文書にしています。

選択範囲とメモ ID の対応、コピーする文字列の組み立て、録音による更新との調整はアプリ側で行います。

コピーでは各メモに含まれる選択部分を取り出し、空の部分を除いて `\n\n` でつなぎます。

区切り文字は Dart の `memoTextSelectionSeparator` から両 OS に渡します。

丸によるブロック選択、本文の太字、右の線、下部の選択バーは文字選択と独立しています。

モバイル以外には Flutter の文字選択実装を残しています。

## 選択範囲内の1回タップへの対応

iOS の `NativeMemoList.swift` と Android の `NativeMemoList.kt` に、選択範囲内の1回タップを判定する処理を加えています。

タップする前から選ばれている面に触れ、1回タップと確定した場合に、既存の選択解除処理を呼びます。

タップ位置は文字の位置だけで近似せず、OS の選択領域から判定するため、選択色が付いたブロック間の余白も対象です。

iOS は OS の長押し・ダブルタップ・ドラッグの認識を優先し、Android は `GestureDetector.onSingleTapConfirmed` で1回タップを区別します。

この操作では、選択色・つまみ・メニューを閉じ、丸によるブロック選択は保ちます。

| iOS シミュレーターでの確認 | 結果 |
| --- | --- |
| 選択中の語の内側を1回タップ | 選択色・つまみ・メニューが消える |
| 1文字のピリオドを選択して内側をタップ | 狭い選択範囲でも解除できる |
| 全件選択後、ブロック間の選択色をタップ | 文字のない部分でも解除できる |
| 選択中の語をダブルタップ | 1回タップによる解除と誤判定せず、選択が残る |
| メニューのコピー | 選択した「Yeah」とクリップボードの内容が完全一致し、選択が残る |
| 文字選択中に丸を押す | 文字選択が残り、ブロックも選ばれる |
| 丸と文字の両方を選択し、選択中の文字をタップ | 文字選択だけ解除され、丸の選択と選択バーが残る |

この対応では確認用メモを追加していません。

`flutter analyze lib`、iOS シミュレータービルド、Android デバッグ APK のビルド、`git diff --check` は成功しています。

長押し・つまみのドラッグとの共存、および Android での操作は、以下の操作環境の制約により実操作での確認が残っています。

## 画面下端の余白への対応

`listening_page.dart` でネイティブ一覧の外側に設けていた下部の安全領域の余白を取り除き、本文の表示領域と右の縦線を画面下端まで広げています。

`listening_selection_bar.dart` にバーの表示高さを返す関数を設け、バーが出ている間だけ、その高さに合わせて一覧を押し上げています。

iOS の `NativeMemoList.swift` では、一覧の高さ変更に伴うスクロール位置の調整後に縦線の描画領域を配置し、バーの上辺で線が途切れないようにしています。

| iOS シミュレーターでの確認 | 結果 |
| --- | --- |
| 通常の一覧表示 | 下端の白い帯がなくなり、本文の表示領域と縦線が画面下端まで広がる |
| 丸を押して選択バーを表示 | 本文がバーの上へ移動し、縦線がバーの上辺までつながる |
| 選択バーの「解除」 | バーが消え、一覧が画面下端までの表示に戻る |
| バー表示中の語のダブルタップ | OS の選択色・つまみ・メニューが表示される |
| 選択中の語を1回タップ | 文字選択だけ解除され、丸の選択と選択バーが残る |

`flutter analyze lib`、iOS シミュレータービルド、`git diff --check` は成功しています。

Android にも共通の余白計算を適用していますが、この下端調整の実画面確認は iOS のみです。

この対応では確認用メモの追加、テストの作成、`dart format`、コミット、push、マージは行っていません。

## 確認できなかったこと

操作ツールのドラッグは、このアプリだけでなく iOS 標準の「設定」の一覧でもスクロールになりませんでした。

そのため、長押しからの選択開始、つまみのドラッグ、つまみの交差、端での自動スクロール、スクロール中の選択保持は実操作での確認が残っています。

ダブルタップによる語の選択と、メニューによる画面外を含む全件選択は確認済みです。

検索欄への文字入力を操作ツールで成立させられなかったため、検索結果に限定した全件選択は実操作で確認できていません。

選択中の削除・追記・新規メモ追加、打ち出し中の選択除外、空のメモや文字を含まない境界だけを選んだ場合は、処理を実装していますが、シミュレーターでの条件をそろえた確認は残っています。

Android はデバッグ APK のビルドを確認していますが、エミュレーターと実機での文字選択操作は未確認です。

## 挙動と残る課題

メニューの項目、配置、選択色、つまみの交差時の動きは OS に従うため、OS のバージョンや端末によって差があります。

iOS では OS の配置判断により、メニューが検索欄に重なる位置へ表示される場合があります。

その位置の「コピー」も押せることを確認していますが、メニューを本文領域内に限定する配置制御は入れていません。

「すべてを選択」は OS のメニューに残しており、現在の一覧全件を対象にします。

選択中は既存メモの本文を保持するため、その間の追記は選択を解除すると表示されます。

全件を1つの文書として保持・計測するため、Flutter のブロック単位の遅延生成とはメモリ使用量と更新コストが異なります。

約1,300件での表示と全件コピーは確認していますが、処理時間やメモリ使用量は測定しておらず、長文・大量のメモ・連続した録音更新での性能確認は残っています。
