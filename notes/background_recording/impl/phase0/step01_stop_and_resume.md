# Step 1: 背面で録音を止め、前面で再開する

## ひとことで言うと

背面に回ったら録音を止め、前面に戻ったら再開する。これをアプリ自身の手でやる。
設定（ON / OFF）はまだ読まず、どちらでも同じ挙動（背面で止まる）にする。

## なぜやるか

今のアプリには「止める・再開する」コードが1行もない。背面で止まっているのは OS がマイクを切っているだけで、アプリ側の stop() が呼ばれないため flush が走らず、背面に入る直前の発話は成り行き任せ。復帰後に録音が戻る保証もない。

そして、この「背面で止める処理」が後続ステップの分岐点になる。

- Android（Step 2）: 設定 ON のときはこの停止をスキップし、フォアグラウンドサービスで録り続ける
- iOS（Step 5）: `UIBackgroundModes` を宣言すると OS は止めてくれなくなり、設定 OFF を実現できるのはこの stop() だけになる（→ `../../ios.md`）
- 設定 UI の無効側の説明文「アプリがバックグラウンドに移ると録音を止め、フォアグラウンドに戻ると再開します。」が、ここで初めて実装として真になる

## どんな実装をするか

`ListeningNotifier`（`lib/providers/listening_providers.dart`）に `AppLifecycleListener` を持たせる。

パイプラインの所有者が停止・再開も担い、autoDispose なので画面を離れれば監視ごと消える。

パイプライン側は stop() → start() の再呼び出しに耐える作りが済んでいるため、変更しない。


| 通知                       | 動作                                                        |
| ------------------------ | --------------------------------------------------------- |
| paused                   | `stop()`。flush が直前の発話を確定し、メモとして保存される                      |
| resumed                  | `start()`。録音中なら何もしないため、覗いただけの復帰でも安全                       |
| inactive・hidden・detached | 何もしない。コントロールセンターや通知シェードを引き出しただけで録音を切らない（→ `../../ios.md`） |


```text
背面へ:   resumed → inactive → hidden → paused   ← ここで stop()
前面へ:   paused → hidden → inactive → resumed   ← ここで start()
覗くだけ: resumed → inactive → resumed           ← 何も起きない（録音は続く）
```



また、起動直後に背面へ回られると、パイプライン生成前に paused が来て素通りする。

`_startPipeline()` の完了時にライフサイクル状態を確認し、既に paused なら止めて整合させる。
