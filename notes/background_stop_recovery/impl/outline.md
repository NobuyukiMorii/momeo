# 背面で録音が止まったときの立て直しと知らせ 実装計画（iOS）

今と変わること:

- 今は、背面で録音が黙って止まると、momeo が気づく前に iOS に眠らされ（止まってから約5秒）、そのまま終了させられる。画面上部の「録音中・経過時間」だけが残り、タップするとスプラッシュから起動する
- 直したあとは、録音が止まった瞬間に気づいて、眠らされる前に録音を再開する。再開できなかったとき・momeo ごと止まったときは、Live Activity が「録音が止まりました。タップで再開」に変わり、同じ文言の通知も届く。タップすると録音が再開する

進め方:

- 1 step = 1 commit = 1つの目的
- 各 step は `phaseN/stepNN_名前/` に置く（計画は `plan.md`。説明資料の HTML は、頼んだときだけ作る）
- iOS は release ビルドで確かめる（`make run d=<端末> mode=release`）。背面の挙動は端末ログ（`subsystem == "jp.momeo"`）で確かめる
- Android はフォアグラウンドサービスで動いていて、今回の止まり方は起きていないので対象外

---

## 調べて分かったこと（2026-11-01 の端末ログ）

```text
LINE 通話が録音を中断 → 5秒で通話終了 → record が録音を再開
→ 0.6秒後、録音エンジンが黙って止まる（直前にカテゴリ変更の経路の変化）
→ iOS が約5秒で momeo を眠らせる（見張りは5秒無音で動くので間に合わない）
→ 1時間後、メモリ回収で他のアプリと一緒に終了
```

- 録音エンジン（AVAudioEngine）は、経路やカテゴリが変わると止まり、`AVAudioEngineConfigurationChange` の知らせを出す。record はこれを見ていないので、止まったことを Dart に伝えない
- この知らせは momeo のネイティブ側で、どのエンジンのものでも受け取れる（record の中身に触らずに済む）

## 全体の流れ

```text
Phase 1  止めない（止まった瞬間に再開する）
Phase 2  止まったら知らせる
Phase 3  仕様書
```

## Phase 1 止めない

見張りの「覗きに行く」やり方をやめて、止まった知らせを合図に動く。覗きに行く見張りも、iOS の猶予（約5秒）に間に合う速さにして残す。

| step | やること |
| ---- | ------------------------------------------------------------ |
| 1    | 録音エンジンが止まった知らせを Dart へ流し、すぐ再開する |
| 2    | 中断が終わったら、少し待って音が届いているかを確かめる |
| 3    | 覗きに行く見張りを、iOS の猶予に間に合う速さにする |

- step 1: 今の「機器の抜き差しの知らせ」（`AudioSessionChannel` の EventChannel）に、録音エンジンが止まった知らせを足す。Dart は受け取ったら待たずに `_restartRecording` する
- step 2: 中断の終わり（record が `record` に戻ったとき）を合図に、機器の抜き差しと同じ「1秒待って 0.5秒音が無ければ再開する」確認を走らせる
- step 3: 2秒間隔・5秒無音 → 1秒間隔・2.5秒無音（音のかたまりは約20ms ごとに届くので、誤って再開することはない）

※ 背面で再開が通るかは、まだ実機で確かめていない（セッションは有効なままなので通る見込み）。step 1〜3 のあと端末ログで確かめ、通らなければ Phase 1 に「録音を record に頼らず Swift で持つ」step を足す。

## Phase 2 止まったら知らせる

momeo が生きている間は「まだ大丈夫」を一定間隔で送り続け、途絶えたら iOS 側が自動で「止まりました」に切り替える（momeo が眠らされた・終了させられたあとは、momeo は何もできないため）。

| step | やること |
| ---- | ------------------------------------------------------------ |
| 4    | Live Activity に期限（staleDate）を付け、生きている間は先へ延ばし続ける |
| 5    | 期限が切れたら「録音が止まりました。タップで再開」と表示する |
| 6    | 同じ期限で通知を予約し、生きている間は先へ延ばし続ける |
| 7    | 再開できないと分かったら、期限を待たずにすぐ知らせる |
| 8    | タップで開いたら録音を再開し、「止まりました」を片付ける |

- step 4: live_activities は更新時に期限を渡せないので、期限の付け替えは Swift で `Activity.update(_:)` を直接呼ぶ。延ばす間隔は30秒、期限は90秒先
- step 5: Widget 側で `context.isStale` を見て文言を切り替える。経過時間の表示は止める
- step 6: 通知は Swift で `UNUserNotificationCenter` に予約し直す（同じ識別子で上書き）。通知の許可は、iOS でバックグラウンド録音で初めて録音を始めるときに尋ねる（すでに有効にしている人にも尋ねられるよう、設定の切り替え時ではなく録音の開始時にした）。意図した停止・アプリスイッチャーからの終了では予約を取り消す
- step 7: 背面で `_restartRecording` が失敗したら、Live Activity をすぐ「止まりました」にし、通知もすぐ出す
- step 8: 通知・Live Activity のタップで開いたときは、今の起動・復帰の流れで録音が始まる。そこで予約中の通知と「止まりました」の表示を片付ける

※ 期限90秒は「止まってから最長で約2分で知らせる」目安。短くするほど延ばす回数が増える（30秒に1回なら電池への影響は小さい）。
