# 準備ゲート仕様

## 概要
リスニングに入る**直前の1か所**で、文字化エンジン（OS の文字起こしと、発話を区切る音声 isolate）の準備が完了しているかを判定するゲートです。

- **準備済みなら素通り**: 待ち画面は表示されず、そのままリスニング画面へ進みます。
- **未完了なら足止め**: 待ち画面で現在の状況を表示し、準備が完了したら自動でリスニング画面へ進みます。ユーザー操作は不要です。

エンジンの準備（OS の文字起こしが使えるかの確かめと、音声 isolate の立ち上げ）は起動と同時に裏で始まっており、スプラッシュ・権限フローの間に終わるため、**通常起動は素通りが基本**です。足止めが起きるのは主に、OS が言語のモデルをまだ端末にダウンロードしていないとき（初めて使う言語など）です。

## 画面遷移上の位置

```text
App Start（エンジン準備を裏で開始）
→ Splash
→ Permission
→ 【 準備ゲート 】 ── 準備済み ──→ Listening Screen
        └─ 未完了: 待ち画面で足止め → 完了したら自動で進む
```

待たせる処理はこの1か所に集約されており、スプラッシュや権限フローに足止めはありません。

## 待ち画面の表示状態（UI State）

待ち画面は、スプラッシュの最後の録音ボタン（輪＋黒丸）を画面中央に止めたまま出し、スプラッシュの続きに見せます。最初の権限チェック中も同じ録音ボタンを出します。ダウンロード中・失敗・使えない端末のときだけ、録音ボタンの下に、いま何が起きているかを短いひとことで出します。録音ボタンの位置はどのフェーズでも変わりません。**進捗バーや数字は置きません**。ダウンロードの進み具合は、録音ボタンの外側の輪で見せます。

| フェーズ (Phase) | 表示テキスト | 状況 |
| --- | --- | --- |
| loading | （文字なし。録音ボタンだけ） | エンジンの準備中（OS の文字起こしの確かめ・音声 isolate の立ち上げ） |
| downloadingLanguage | `Downloading the language model`（進み具合が分からないときは末尾がドット） | OS が言語のモデルをダウンロード中 |
| retrying | `Retrying` | 準備に失敗し、自動再試行を待っている |
| tryRestarting | `Please restart the app` | 連続失敗が閾値を超え、再起動を提案している |
| unsupported | `Not available on this device` | OS の文字起こしが使えない端末（端末内の音声認識が無い、優先する言語のどれにも対応していない） |

- 録音ボタンの下のテキストの切り替えは、**フェーズが変わったときのみ**スライド演出で行います。テキストは中央揃えです。
- `Downloading the language model` と `Retrying` は、「処理中」を示すドットアニメーション付きです。録音ボタンはスプラッシュの続きに見せるため、`Please restart the app` はユーザーへの依頼のため、`Not available on this device` は待っても変わらないお知らせのため、動きを付けません。
- ダウンロードの進み具合は、分かるときだけ、録音ボタンの外側の輪を12時の位置から時計回りにその割合だけ伸ばして見せます。伸びていない部分は何も描きません。進み具合は1秒おきに問い合わせ、次の値まで1秒かけてなめらかに伸ばします。
  - 一周の輪から進み具合の表示に切り替わるときは、輪をいったん消し、0 から今の割合まで伸ばします（一周から縮んで見えないようにするため）。
  - 進み具合が分からないときは、輪は一周のまま、文言の後ろでドットを動かします。
  - iOS は、OS がダウンロードの依頼に付けて返す進み具合を使います。
  - Android は 14 以降だけ、ダウンロードを頼むときに進み具合を知らせてもらいます。Android 13 は知らせてもらう方法がないので、常にドットです。
  - 最初の問い合わせの答えが返るまでの一瞬は、文言だけを出します（数字が取れる端末で、ドットを一瞬見せないため）。
  - 知らせが届く前や、アプリを開き直してダウンロードの途中から待つとき（momeo が頼んだダウンロードではないとき）はドットになります。
  - Android がダウンロードを後回しにしたとき（Wi-Fi 待ちなど）も、ドットに戻します。

## 表示の確認用: ダウンロード中のふり

`--dart-define=FAKE_LANGUAGE_DOWNLOAD_SECONDS=10` を付けてビルドすると、最初の問い合わせから指定秒数のあいだ、OS の返事を「ダウンロード中」に差し替えます（`lib/platform/os_transcriber_channel.dart`）。進み具合も、経過時間に合わせて 0〜100% に増えていくふりをします（輪が伸びていく）。`--dart-define=FAKE_LANGUAGE_DOWNLOAD_HIDE_PROGRESS=true` を足すと、進み具合は分からないまま（一周の輪とドット）にします。差し替えるのは OS の返事だけで、5秒おきの確かめ直し・フェーズの判定・待ち画面の表示は本物と同じコードが動きます。実際のダウンロード時間や、OS が出す確認の画面・通知は再現しません。指定しなければ何もしません。

## フェーズの判定ルール

エンジンの準備状態だけで判定します。準備では、OS の文字起こしに「すぐ使えるか」を問い合わせ、返事は `ready`（すぐ使える）・`downloading`（言語のモデルのダウンロード中）・`unsupported`（端末か言語が対応していない）の3つです。

1. **言語のモデルのダウンロード中** → `downloadingLanguage`。確かめ直している最中も、表示を揺らさないよう同じフェーズのままにします。
2. **エンジンが失敗中**（再試行の実行中は除く）→ 使えない端末なら `unsupported`。それ以外は `retrying`、ただし再起動提案フラグが立っていれば `tryRestarting`。
3. **それ以外** → `loading`。

## 失敗からの自動復帰（自動再試行）

準備が失敗しても、**ボタンなし・ユーザー操作ゼロ**で自動再試行し続けます。再試行ループはエンジン側（provider）が持ち、待ち画面は状態を表示するだけです。

- **バックオフ**: 再試行の間隔は失敗のたびに 2 → 4 → 8 → 16 → 30秒 と広がり、以降は30秒間隔を維持します。
- **言語のモデルのダウンロード中**: 失敗には数えず、5秒おきに準備をやり直して、モデルが入ったかを確かめます。ダウンロードは OS が進めるので、momeo は頼むだけです（iOS は `AssetInventory`、Android は `triggerModelDownload`）。
- **使えない端末**: 再試行しません。何度やっても結果は同じためです。
- **再起動の提案**: 連続5回失敗したら表示を `Please restart the app` に切り替えます。無限の `Retrying` だと固まったアプリと見分けがつかないためです。**切り替え後も裏では30秒間隔で再試行を続ける**ので、待てば直る失敗（通信断など）は再起動なしで復帰します。
- **復帰**: 準備が成功すると失敗カウントと再起動提案はリセットされ、自動でリスニング画面へ進みます。失敗原因の分類（直る系/直らない系）はしません。
