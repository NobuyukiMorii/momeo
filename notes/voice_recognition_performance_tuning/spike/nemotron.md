# S8 `nemotron` — Nemotron 3.5 に差し替えて比べる

> **状態（2026-09-21）**: 実施済み。計画は `main` の [plan/spike/nemotron.md](../plan/spike/nemotron.md) を正本とする。
> ブランチ: `spike/voice_recognition_performance_tuning/nemotron`（S6 `145046b` から。S6 は S4 `8e75216` の子）。**`main` にはマージしない。**
> **この spike は一度も音を出していない**（マイク・スピーカー・音量・通知に一切触れていない）。

## 1. 飛ばす条件の判定

計画書 §1 の飛ばす条件は「**S6 と S7 の両方で日本語が明確に落ちていたら実施しない**」である。

**当たらない。実施する。** S6・S7 のどちらでも日本語は落ちておらず、むしろ両方が現行の落とした節を復元した（[sensevoice.md](sensevoice.md) §4、[qwen3.md](qwen3.md)）。

## 2. 無音で進めるための作り

S6・S7 と同じ方針で、**マイクにもスピーカーにも触れない入口**を用意した。

- `lib/main_spike_nemotron.dart`: 通常の main / ListeningPage を通らない入口。マイク・プレイヤー・録音サービスを起動しない
- 既存 `SttFixedAudioSection` を再利用。画面で候補を選べる（現行 NeMo / Nemotron 自動 / Nemotron 日本語固定）
- `--dart-define=S8_AUTO_RUN=true` で起動後に 5回（NeMo 1・自動 2・日本語固定 2）を自動実行
- **音声の置き場所も画面で選べる**（S2 で作ったものを持ち込んだ）。凍結コーパスと台本コーパスを、ビルドし直さずに切り替えられる
- 結果・状態は `files/spike_nemotron/`

## 3. モデルの出所

- 475,276,334 bytes、SHA256 `adbdd5e9fef87300c37cebfcfc4f1ebe56845c860c8a760af0a1dd65ce9beed3`

## 4. 実装で分かったこと（採用判断の材料）

### 置き換えたクラス

**この候補だけ、認識器のクラスの系統が変わる。**

| | 現行 NeMo・SenseVoice・Qwen3 | **Nemotron** |
|---|---|---|
| 認識器 | `OfflineRecognizer` | **`OnlineRecognizer`** |
| ストリーム | `OfflineStream` | **`OnlineStream`** |
| 呼び出し | `acceptWaveform` → `decode` → `getResult` | `acceptWaveform` → **無音を足す** → `inputFinished` → **`isReady` の間 `decode` を回す** → `getResult` |
| 言語の指定 | 認識器の設定（SenseVoice） | **ストリームごと**（`setOption('language', …)`） |

戻り値の型が違うので、`_AudioEngine` が持っていた `OfflineRecognizer` 型のフィールドをそのまま使えない。
**`_Transcriber`（サンプルを渡すと文字が返るもの）という呼び出し口を1つ挟み**、`_OfflineTranscriber` と `_StreamingTranscriber` に分けた。呼ぶ側（`_transcribe`）は1行のままになる。

### つまずいた点（想像で書くと外れるところ）

- **特徴量は128次元。** `sherpa_onnx` の `FeatureConfig` の既定は80で、渡さないと黙って読み違える。上流の公式例（`test_asr_streaming_nemotron.js`）がこのモデルにだけ明示的に128を指定していることで気づいた
- **`enableEndpoint` を切った。** 既定は `true` で、1ファイルの途中で区切られると前半の結果が消える。**1ファイル＝1発話**として扱うために切った
- **言語は `ja` / `auto`。** 計画書が「`ja` か `ja-JP` か着手時に確認する」としていた点は、ライブラリの doc コメントと上流 README の両方が `ja` と `auto` と書いている
- **`decodingMethod` は `greedy_search` のまま**（計画書 §8）
- **末尾に足す無音の長さで結果が変わる。** 詳細は次項

### 末尾に足す無音は、上流の例をそのまま写すと足りない

逐次型は `inputFinished` の前に無音を足さないと最後が出ない。**上流の例は 0.4 秒**だったのでそのまま写したが、**このモデルのチャンクは 1120ms あり、0.4 秒では最後の1チャンクが埋まらない。**

1.6 秒に上げると、56件中13件で語尾が戻った。

| | 0.4 秒 | **1.6 秒** |
|---|---|---|
| E-1 | `…almost ready for` | `…almost ready for` **`release`** |
| F-E-1 | `…before Friday` | `…before Friday` **`afternoon`** |
| Z-1 | `…把我说的话变成` | `…把我说的话变成`**`文字`** |
| F-J-1 | `…忘れないうちに残して` | `…忘れないうちに残して`**`おきたい`** |

**空の結果の件数は変わらない**（15件のまま）。語尾だけの問題である。

**最初の2回の測定（凍結コーパス・台本コーパス）は 0.4 秒で流しているため、Nemotron に不利な条件になっている。** 正しい条件で取り直した結果を §6 に載せる。

**後続への教訓**: 逐次型を測るときは、**末尾の無音をチャンク長以上にする**。上流の例は参考であって仕様ではない。

### 体感の作業量

S7 の状態からの差分は、認識器側 **+159 / -44 行**、画面側 **+72 / -5 行**（画面側の約半分は S2 で作った置き場所選択の持ち込みで、S8 固有ではない）。
**足場を作り直していないことが効いている。** S6 で作った無音実行・RAM 採取・復元の仕組みと、S7 で作った「候補ごとの切り替え」をそのまま使えた。

**したがって S8 は「RAM と詰まりで条件外」では落ちない。** S7 を落とした基準では落ちない。**落ちるとすれば中身である。**

### 6.3 英語の表記が定まるか（課題②の本題）

**定まらない。そして英字では出ない。**

| 語 | 現行 | SenseVoice | **Qwen3** | **Nemotron** |
|---|---|---|---|---|
| Facebook | `フェceブok` | `フェイスブック` | **`Facebook`** | （語頭なので落ちた） |
| iPhone | `iphone` | `アイフォン` | **`iPhone`** | `アイフォン` |
| AirDrop | `airdrop` | `エアジョロ` | **`AirDrop`** | `エアドロップ` |
| Mac / Samsung | `マック`/`サムスン` | `マーク`/`サムスン` | **`Mac`/`Samsung`** | `マック`/`サムスン` |
| ITリテラシー | `itリテラシー` | `アティイテラス` | `IT 依存率` | `itらスイン` |
| I think | `iiceting`/`iicsinck` | `アインク`/`アイシンク` | **`I think`（2回とも同一）** | `アイスンク`/`アイシンク` |
| I believe | `i’beleve` | `アイブルーブア` | **`I believe`** | `アイブリーブ` |

**大文字と句読点が効くのは、発話まるごとが英語のときだけである。** 日本語の文中に混ざった英語は、SenseVoice と同じくカタカナに倒れ、**しかも `アイスンク` と `アイシンク` で揺れる**。

**課題②に有効な手は、依然として Qwen3 だけである。** そしてその Qwen3 は RAM で条件外だった。**「解ける手はあるが、その手は積めない」**という行き止まりが、これで2候補ぶん確かめられた。

### 6.4 言語指定（`auto` か `ja` か）

**`auto` を使う。`ja` 固定に利点はない。**

`ja` に固定すると**英語4件がすべて空になり**、普通話も崩れる（`我是日本人` → `市边人`）。空の結果は 5件 → 9件に増える。25行中14行で差が出るが、**日本語の行では改善していない**。

S6 の結論（`ja` 固定は普通話を壊す）と同じ向きだが、**Nemotron はさらに強く、英語を丸ごと捨てる**。

### 6.5 相づちを1件も認識できない（**採否を分ける**）

台本コーパスの相づち9件は、**現行が 9/9 正解、Nemotron は 0/9**。

| 長さ（前後0.5秒込み） | 正解 | 現行 NeMo | Nemotron |
|---|---|---|---|
| 1.35〜1.51秒 | `うん` / `はい` | **全て正解** | **全て空** |
| 1.57〜1.96秒 | `なるほど` | 全て正解 | **全て正解** |

**長さの問題ではない。** 1.51秒と1.57秒でほぼ同じなのに結果が完全に分かれる。`うん`・`はい`（2モーラ）が全滅し、`なるほど`（4モーラ）は全部出る。

**前後0.5秒の無音を足しても変わらない**（§6.6 の `__pad` でも同じ6件が空）。助走の不足ではなく、**短い語そのものを出せない**。

**S2 で「相づち9件すべて正しく認識（0.35〜0.96秒）」と確認した帯である。** 相づちは momeo の用途の中心にあり、ここが空になることは**設定では埋められない**。

### 6.6 語頭の欠けは入力側。ただし Nemotron ではもっと痛い

S2 で作った `spike_headcut`（同じ発話の「切り出し後」と「前後0.5秒つき」28組）をそのまま流した。

**28組中22組で出力が変わった。**

| | 切り出し後 | **前後0.5秒つき** |
|---|---|---|
| E-1 | `Think this feature is almost ready for` | **`I think`** `this feature is almost ready for` |
| E-2 | `Application records…` | **`This`** `application records…` |
| Z-1 | `那个应用…` | **`这个`**`应用…` |
| F-J-1 | **`脳`**`の打ち合わせで…` | **`昨日`**`の打ち合わせで…` |
| F-J-2 | **`最終`**`の火曜日までに…` | **`来週`**`の火曜日に…` |

**頭が欠けると、無音になるのではなく別の語に化ける。** `昨日`→`脳`、`来週`→`最終`。**読んでも間違いに気づけない。**

**S2 の結論（取りこぼしは語頭だけ・原因は入力側）は、この候補でも成り立つ。** ただし S2 では実害が英語の語頭に限られていたのに対し、**Nemotron では日本語でも語が化ける**。1120ms のチャンクで動く逐次型は、**現行より長い助走を必要とする**。

**採るなら「切り出しに前余白を足す」が前提条件になる。** S2 が挙げた後続の介入が、ここでは任意ではなく必須になる。

### 6.7 逐語の採点（台本コーパス・末尾無音を直した条件）

正解が喋る前から確定している唯一のコーパス。**日本語を含む文だけを採点し、英語・普通話は読み比べに回した**（カタカナ音写に文字一致率を当てると、内容ではなく表記の差を測ってしまう）。漢数字は算用数字に揃えてから比べている。

| F-J-2 | 最終判定用 | **89.9%** | 75.8% |
| F-J-3 | 最終判定用 | **96.5%** | 94.0% |

**長い発話では明確に上回る場面もある。** 現行が `あ日の朝一番に` / `あしたの朝一番に` と揺れる行で、Nemotron は2回とも `明日` と漢字で出している。

**数字は漢数字で出る。** `1600年` を現行は `162年`（誤り）、SenseVoice は `16002年`（誤り）、**Nemotron は `千六百年`（値は正しい）**。値は合うが表記が違うので、採点時に揃える必要があった。課題②と同じ「表記が定まらない」問題の一種である。

## 7. 後続への申し送り

### この spike で確定したこと

- **S8 は RAM・速度では落ちない。** PSS 1,014MB は現行より小さく、実時間の 25〜28%
- **英語と普通話は出る。** 大文字・句読点つき。**ただし発話まるごとが英語のときだけ**
- **日本語の長い発話は互角。** 最終判定用6文で3勝3敗
- **相づち（2モーラ）を1件も出せない。** 前余白を足しても変わらない。**これは設定で埋められない**
- **語頭の欠けは入力側**（S2 の結論と同じ）。ただし**逐次型では日本語でも語が化ける**ため、採るなら前余白が必須
- **`auto` を使う。`ja` 固定は英語を丸ごと捨てる**
- **課題②は解けていない。** 日本語の文中では英字が出ず、表記も揺れる

### 採用の判断はこの spike ではしない

計画書 §9 のとおり、**3候補が出そろっただけである。** `main` に戻って全記録を見たうえで決める。ただし**この spike から持っていくべき事実**を挙げる。

| | RAM | 日本語 | 課題②（表記） | 致命的な欠点 |
|---|---|---|---|---|
| 現行 NeMo | 1,262MB | 基準 | 解けない | 英語・普通話が崩壊。節を落とす |
| **SenseVoice** | **778MB** | 落ちない | カタカナ | — |
| Qwen3 | 4,010MB | 落ちない | **英字で出る** | **RAM で条件外** |
| **Nemotron** | 1,014MB | **相づちが全滅** | カタカナ・揺れる | **相づちが全滅** |

**課題②に有効な手は Qwen3 だけで、その Qwen3 は積めない。** これは2候補で独立に確かめられた。

### 新しく増えた宿題

- **「切り出しに前余白を足す」の効果と副作用を測る spike。** S2 が挙げたもの。**Nemotron を採るなら必須、現行のままでも英語の語頭に効く**。ただし S2 で「停止直後①が -13.8pt 悪化」する例が出ているので、余白は常に得ではない
- **逐次型を測るときは、末尾の無音をチャンク長以上にする**（§4）。上流の例は参考であって仕様ではない
- **相づちの扱いを評価軸として明示する。** これまで「空の結果の件数」としか数えていなかったが、**2モーラの相づちを出せるか**は候補を分ける軸だった。台本コーパスに9件あるので、以後の候補はここを必ず見る
