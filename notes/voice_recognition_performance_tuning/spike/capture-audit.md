# S2 `capture-audit` — 収音と発話境界を診断する

> **状態（2026-09-21）**: 実施済み。計画書 §2 が挙げた **8条件をすべて実測**した。
> 計画は `main` の [plan/spike/capture-audit.md](../plan/spike/capture-audit.md) を正本とする。
> ブランチ: `spike/voice_recognition_performance_tuning/capture-audit`（S3 `96cf384` から）。**`main` にはマージしない。**

## 結論

**取りこぼしは1か所だけ見つかった。語頭である。**

**VAD が切り出す位置は、発話の始まりより遅れることがある。** 30発話中9件で、切り出しの手前に発話と同じ大きさの音が残っていた。最大 150ms のものでは、**そこに乗っていた語が認識結果から丸ごと消えていた**。余白を戻して同じ認識器に流すと、**その語が出る**（§5）。**モデルが読めなかったのではなく、渡っていなかった。**

**残る7条件では問題が出なかった。** 語尾・相づち・小声・遠距離・生活音・機器切替・30秒境界は、いずれも取りこぼしを起こしていない（§4）。

> **相づちについての追記（2026-09-21）**: このあとの spike（前余白・S5）は、**切り出し済みの wav を VAD に通し直す経路**で測ったため、「0.5秒未満の相づちが落ちる」という結果を出した。
> **それは測り方の産物だった。** ここに残した生 PCM のセッション録音を連続音のまま流し直すと、**現行設定のままで相づちは 9/10 正しく出る**（[segmentation.md](segmentation.md) §7）。**この記録の観察が正しかった。**

**したがって S5 `segmentation` の動機は、この spike からは出てこない。** 見つかったのは無音しきい値や最短発話の問題ではなく、**切り出しの開始位置**である。直すとすれば「しきい値を振る」ではなく「**切り出しに前余白を足す**」という別の介入になる。ただし余白は常に得ではない（§5）。

**実害が確認できたのは英語の語頭だけである。** 日本語では、余白を戻しても一致率が動かなかった（§5）。

## 1. 測定の作り

S3 の録り込み経路に、**生 PCM をそのまま1本の wav にためる経路**を debug 限定で足した（`lib/stt/capture_audit.dart`）。認識入力・しきい値・端数処理は変更していない。

VAD が発話を返すたび、**その発話が生のどの区間に当たるか**を記録する。書き出すのは次の3つ。

- `<時刻>_session.wav` … セッション全体の生 PCM
- `<発話>_raw.wav` / `<発話>_vad.wav` … 同じ発話の「前後 0.5 秒つき」と「VAD が認識器に渡した音」
- `<id>_pairs.tsv` / `<id>_stop.tsv` … 対応区間と、停止時に投入されなかったサンプル数

**対応づけは推測していない。** 生 PCM と切り出しのサンプルが**全件一致したペアだけ** `paired` として書き出す。一致しなければ `unverified` として残す。

メモリは10分ぶんで打ち切る（`overflow`）。診断のために本番の認識を変えない。

### この記録で使わなかったもの

**前日（2026-09-20 21:52）の動作確認1件は集計から外した。** 仕組みが動くかを見るためのもので、条件を決めて喋っていない。

## 2. 測定できる条件

**VAD が作り直された最初の録音だけ**を観測する（`_vad == null` のとき）。停止しても VAD は解放されないため、**アプリを終了してから開き直さないと次のセッションは記録されない**。3回とも終了・再起動してから録っている。

`sherpa_onnx` は **1.13.8**。S4 の申し送り「以後の spike はすべて 1.13.8 の上で行う」に合わせ、枝元（1.13.3）から上げて測った。`pubspec.yaml` の変更はブランチに未コミットで置いてある。

## 4. 条件ごとの結果

計画書 §2 が挙げた8条件すべてを実測した。**問題が出たのは語頭だけである。**

| 条件 | 件数 | 結果 |
|---|---|---|
| **語頭** | 30 | **9件で切り出しの手前に発話と同じ大きさの音。最大 150ms で語が消えた** |
| 語尾 | 30 | 1件のみ 20ms。停止直後の1件で、**本人が聴いて声は入っていないと判断** |
| 短い相づち | 9 | **全件拾って全件正解**（「うん」0.35〜0.38秒 / 「なるほど」0.57〜0.96秒 / 「はい」0.38〜0.51秒）。**2026-09-21 に連続音で再確認済み**（[segmentation.md](segmentation.md) §7） |
| 小声 | 1 | 正しく認識 |
| 遠距離（約2m） | 1 | 正しく認識。語頭 170ms が切れているが**出力は変わらなかった** |
| 生活音 | 1 | **完全に正しい**。暗騒音 -43.7 dBFS（静かな部屋は約 -50 dBFS） |
| 機器切替 | 1 | **完全に正しい**。録音は途切れず、接続後の発話も丸ごと拾えた |
| 30秒境界 | 2 | **割れ目の前後 500ms はどちらも背景音レベル**（-40.8 / -40.4 dBFS、本体は -34 dBFS）。**語は落ちていない** |

### 語頭の切れ方

| 切れた長さ | 件数 |
|---|---|
| 150〜170ms | 2 |
| 30〜50ms | 4 |
| 10〜20ms | 3 |
| なし | 21 |

中央値は 30ms。**大半は軽微で、出力も変わっていない。** 問題になったのは 150ms の1件だけである。

**遠距離の 170ms は「声が切れた」と断定できない。** その発話自体が静かで（ピーク -27.5 dBFS）、判定に使ったしきい値が暗騒音に近い。出力も変わっていない。

### 停止時の端数

`stopListening` は VAD を flush するが、変換バッファの 512 サンプル未満は投入しない。実測は **256 サンプル（16ms）が2回、0 サンプルが1回**。

停止直後の発話では、切り出しの終端が生の終端より**きっかり 256 サンプル手前**だった。ただし**本人が聴いて、その 16ms に声は入っていないと判断した**。

**この端数を精度問題の原因と扱わない。** 16ms は音素1つにも足りず、実測でも語を削っていない。機械が測ったエネルギーは直前 100ms より大きかったが、**耳が声を認めない以上それは声ではない**（ホームに戻すスワイプの触覚音や息の可能性がある）。

### 機器切替について測れていないこと

**切り替えは発話と発話の隙間で起きた。** 1文目が終わってから接続し、そのあと2文目を話している。したがって「**喋っている最中に切り替えたらどうなるか**」は測れていない。

## 5. 語頭の欠けが原因かを切り分けた

**切り出しの手前に音が残っている**ことと、**その語が消えている**ことは、別の話である。モデルが読めなかっただけかもしれない。

そこで、**同じ発話の「切り出し後」と「前後 0.5 秒つき」を、同じ認識器の同じ経路（丸ごと）に流して**比べた。違うのは音だけである。

### 測定が成立していること

30ペア＝56ファイル（前日の1件を除く）を**2回流して 56/56 完全一致**。経路は決定的なので、**差はすべて音の違いから来ている**。

### 英語では語頭が戻った

| | 出力 |
|---|---|
| E-1 切り出し後 | `シディスピーチュイズオストレビーフォーズ` |
| E-1 **余白つき** | **`アイスティinク`**`ディスピーチュイズオースレビーフォーリーズ` |

正解は `I think this feature is almost ready for release.` である。**`I think` は余白つきでしか出ない。**

| | 出力 |
|---|---|
| F-E-1 切り出し後 | `bィゼリー`マイドミートゥ`セイン`ボイス`ピール`フライデーアフヌー |
| F-E-1 **余白つき** | **`プリーズリ`**マイドミートゥ**`セント`**インボイス**`ビュフォール`**フライデーアフェヌ |

正解は `Please remind me to send the invoice before Friday afternoon.` である。**`Please` `send` `before` が余白つきで出ている。**

### 日本語では差が出なかった

正解が確定している日本語19件で、文字の一致率を測った。

| | 切り出し後 | 余白つき | 差 |
|---|---|---|---|
| 平均 | 90.0% | 90.3% | **+0.4pt** |

相づち9件はどちらも 100%。F-J-2 が +7.2pt、小声が +10.0pt 改善する一方、**停止直後の1件は -13.8pt 悪化した**。

**余白を足せば良くなるとは言えない。** 日本語では測定できる差が出ていない。

### この測り方の限界

**英語・普通話は文字の一致率で測れない。** 現行モデルは英語をカタカナに音写するため、ラテン文字の正解との一致率は**内容が合っていてもほぼゼロ**になる。上の英語2件は**出力そのものを読んで判断**した。

前余白は 0.5 秒で固定している。**何ミリ秒あれば足りるかは測っていない。**

## 6. 人が耳で判断したこと

計画書 §4 のとおり、ペアが揃ったところで止まって本人に聴いてもらった。返ってきたのは次の4点である。

| 対象 | 判断 |
|---|---|
| 停止直後の 16ms | **声は入っていなかった** |
| E-1 の語頭 | **切り出し後も `I think` は聞こえる。ただし冒頭の `I` の出だしが切れ、母音が弱い** |
| E-2 の 30秒境界（前半の語尾） | 切れているようには感じない |
| E-2 の 30秒境界（後半の語頭） | 切れているようには感じない |

**E-1 の判断は、機械の測定と食い違わない。** 人の耳には語として聞こえる程度の欠けでも、**モデルは語を落とす**。つまり「人が聴いて分かるかどうか」は、この問題の指標にならない。

あわせて本人から「**切り出したときに前後が少し切れている気がする**」という所見があった。9/30 件で手前に音が残っているという測定と一致する。

## 7. S3 の空の認識結果について

計画書 §5-9 が挙げていた「**空の認識結果になった区間に実際は何が入っていたか**」に答えが出た。

S3 で空だった 6.11 秒には、**本人の英語が入っていた**（`For example, if I speak like this in English suddenly, can you understand.`）。本人が聴いて確認している。

**空だったのは音が無かったからではない。** 現行モデルが英語を1文字も返さなかっただけである。詳細は [current-baseline.md](current-baseline.md) に移した。

## 8. 後続への申し送り

- **S5 `segmentation` の動機は、この spike からは出てこない。** 無音しきい値・最短発話・30秒境界のいずれにも問題が見つからなかった。**ただし `maxSpeechDuration` が効いていない件は S5 で扱う**（S3 で確認済みで、S2 の結果とは独立している）
- **「切り出しに前余白を足す」は別の介入である。** しきい値の調整ではない。効くのは英語の語頭で、日本語では効果が測れず、悪化する場合もある。**やるなら効果と副作用を測る独立した spike が要る**
- **課題②（日本語中の英語）に直結する。** 発話の**先頭にある英単語は丸ごと消えることがある**。表記ゆれとは別の壊れ方である
- **「人が聴いて分かるか」を指標にしない。** E-1 は人の耳には語として聞こえるのに、モデルは落とした
- **生活音と機器切替は問題にならなかった。** 収音側を疑う筋は、この2つについては閉じてよい
- **喋っている最中の機器切替は測れていない。** 必要になったら録り足す
- 生 PCM の保存と対応区間の切り出しはブランチに残す。**S5 でも使える**
