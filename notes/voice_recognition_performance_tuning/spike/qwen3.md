# S7 `qwen3` — Qwen3-ASR 0.6B に差し替えて比べる

> **状態（2026-09-21 早朝）**: 実施済み。**RAM と処理時間で条件外と判断し、打ち切った。**
> **この spike は一度も音を出していない**（マイク・スピーカー・音量・通知に一切触れていない）。
> 計画は `main` の [plan/spike/qwen3.md](../plan/spike/qwen3.md) を正本とする。

## 結論

**Qwen3-ASR 0.6B は採らない。** 理由は精度ではなく、**常駐RAM が現行の3倍（最大 4,010MB）**で、**出力を切らずに認識させると喋った時間の3.9倍かかる**こと。計画書 §9 の「RAM・詰まりで条件外と判断でき、その根拠が記録に残っている」に当たる。

**したがって S9 `hotwords` は実施しない**（計画書 §9 の飛ばす条件）。

**S8 `nemotron` は飛ばさない。** 飛ばす条件は「S6・S7 の両方で日本語が明確に落ちた場合」だが、**日本語は落ちていない**。むしろ S6・S7 の両方が、現行が落としている節を復元した（§4）。

**採らない候補だが、出力は捨てない。** 表記（課題②）について、3候補で最も良い結果を出したのは Qwen3 である（§5）。

## 1. 無音で進めるための作り

S6 と同じ方針で、**マイクにもスピーカーにも触れない入口**を用意した。

- 入口は `lib/main_spike_qwen3.dart` のみ。`ListeningPage`・録音サービス・音声プレイヤーを一切生成しない
- 流すのは S3 が溜めた固定 wav（`files/spike_audio/`）を `readWave` → `transcribeWhole` で直接処理するだけ
- `--dart-define=S7_AUTO_RUN=true` で起動後に条件を通しで自動実行する
- runner（`scripts/run_qwen3.py`）は `keyevent`・通知・音量の操作を一切行わない

## 2. S6 の足場をそのまま使っている

**枝元は S6 `sensevoice` ブランチ**（`145046b`）。計画書は「S4 から枝を切る」としていたが、S6 が作った**無音の入口・runner・集計**は足場であって介入ではないため、作り直さずに引き継いだ（`master.md` §1「足場を作り直さない」）。計画書は枝を切った直後に `main` から取り直している。

足場の側で変えたのは次の2点だけである。

| 変えたもの | 中身 |
|---|---|
| `lib/stt/stt_audio_worker.dart` | 認識器の種類を `SttRecognizerKind`（`nemo` / `senseVoice` / `qwen3`）で選ぶ形に整理した。S6 は「`senseVoiceLanguage` が `null` なら NeMo」という書き方だったが、3種類目が入ると読めなくなるため |
| `lib/pages/dev/catalog/sections/stt/stt_fixed_audio_section.dart` | spike 名で実行内容（候補の並びと回数）を切り替える形にした。S6 の実行内容は変えていない |

**本番のリスニング経路は触っていない。** `stt_providers.dart` と `stt_transcription_section.dart` は既定の `nemo` のまま、呼び出しも変えていない。

## 3. 実行する条件

| 順 | 候補 | 回数 | 何のために |
|---|---|---|---|
| 1 | 現行 NeMo | 1 | **S4 と同じ結果が出ることの確認。** 一致して初めて、差を「モデルの差」と言える |
| 2 | Qwen3 予備確認（長い wav 3件） | 1 | **速度・RAM・出力の途中切れを最初に見る。** ここで条件外なら全件へ進まない |
| 3 | Qwen3 全件 | 2 | 同じ音声を2回流し、**出力が実行ごとに変わらないか**を見る |

**なぜ予備確認を挟むか**: Qwen3 は生成側のモデルで、1トークンずつ decoder を回す。CTC の NeMo・SenseVoice（426 秒の音声を 31〜46 秒で処理）と同じ時間で終わる保証がない。**全件2回を先に始めると、条件外だと分かるまでに何十分も使う。**

長い wav から選ぶのは、**出力長の上限に当たるなら最長の発話で最初に出る**ため（S3 の録り込みの最長は 37.17 秒）。

## 4. 出力長の上限

`sherpa_onnx` 1.13.8 の既定は `maxNewTokens` = 128 / `maxTotalLen` = 512。**画面から 128 / 256 / 512 に変えられるようにした**ので、足りないと分かっても再インストールは要らない（計画書 §5）。

**途中で切れた出力を、モデルの認識能力の不足と取り違えないこと。**

## 5. モデルの取得と配置

`scripts/setup_qwen3.sh`（1コマンド）。

- 取得元は `sherpa-onnx` の `asr-models` リリース、`sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25.tar.bz2`（837MiB）
- 書庫の中は `conv_frontend.onnx` / encoder / decoder の3つの onnx と `tokenizer/`（`vocab.json` ほか）。**現行モデル（単一ファイル）とは形が違う**
- **書庫が指定するパスやリンクは使わず**、こちらで決めた固定の名前へ展開する
- 手元と端末の空き容量をスクリプトの中で確認する（人に確認させない）
- 置いたあと、**1ファイルずつ sha256 を突き合わせる**

### 取得物の検証についての限界

**上流はチェックサムを公表していない。** このスクリプトは初回に取った sha256 を記録し、2回目以降はそれと照合する。**壊れた再取得は弾けるが、初回に取ったものが上流の意図したものかは確かめられない。** S6 の `setup_sensevoice.sh` に書かれた digest も出所は同じである。

## 6. `tokens.txt` を渡さない理由

Qwen3 は `tokenizer/` ディレクトリから語彙を読むため、`OfflineModelConfig.tokens` を使わない。**上流の `offline-model-config.cc` が `qwen3_asr.conv_frontend` が空でないときは `tokens` の存在確認を飛ばす**ことを確認したうえで、空文字を渡している。想像で NeMo の `tokens.txt` を流用していない。

## 7. 測定のしかた（S6 と同じ）

`scripts/run_qwen3.py` が、入れ替え前の APK・評価音声・ラベル・設定・DB をバックアップし、S7 の profile APK を `adb install --no-streaming -r` で上書きし、約2秒間隔で `dumpsys meminfo` を取り、結果を回収してから**元の APK に戻してアプリを停止したままにする**。既定のタイムアウトは 5400 秒（S6 の 1200 秒では足りない見込みのため）。

```bash
flutter build apk --profile --target-platform android-arm64 --no-pub \
  -t lib/main_spike_qwen3.dart --dart-define=S7_AUTO_RUN=true

python3 scripts/run_qwen3.py --serial <adb-serial> \
  --apk build/app/outputs/flutter-apk/app-profile.apk \
  --out <測定ディレクトリ>
```

**途切れたときは、まず測定ディレクトリの `run.json` を見る。** 無ければ runner がまだ測定中か元 APK の復元中なので、**別のインストールや新しい runner を重ねて起動しない。**

## 8. 測定が成立していることの確認

2回インストールして測った。**どちらの回でも、先頭で現行 NeMo を流している。**

| 測定 | 条件 | 現行 NeMo と S4 の一致 | 端末の復旧 |
|---|---|---|---|
| `session_20260921_s7` | NeMo ×1 / 予備確認 ×1 / Qwen3 上限128 ×2 | **25/25 一致（差分0行）** | 音声・APK とも復元を検証済み |
| `session_20260921_s7_long` | NeMo ×1 / Qwen3 上限512 ×1 | **25/25 一致（差分0行）** | 同上 |

**2回とも基準が S4 と一致しているので、2つのセッションの Qwen3 同士も比べてよい。** 観測された差はモデルと設定に帰属する。

**Qwen3 は決定的である。** 上限128で同じ音声を2回流して **25/25 一致**。温度 1e-6・seed 42 の既定のままでも、生成側のモデルが実行ごとに揺れることはなかった。

## 9. 機械が測れた範囲

### 打ち切りの根拠

| 項目 | 現行 NeMo | SenseVoice（S6） | **Qwen3 上限128** | **Qwen3 上限512** |
|---|---|---|---|---|
| 最大PSS | 1,265MB | 778MB | 3,843MB | **4,010MB** |
| 426.05秒の処理時間 | 46.9秒 | 30.9〜42.4秒 | 258秒 | **1,655秒** |
| 実時間比 | 0.11 | 0.07〜0.10 | 0.61 | **3.89** |
| 空の結果 | 1件 | 0件 | 2件 | 2件 |
| 異常終了 | なし | なし | なし | なし |

**RAM の内訳が悪い。** 最大時の PSS 3,843MB のうち **Native Heap が 2,728MB** を占める。ファイルの mmap ではなく実体の確保なので、OS が捨てて逃がせない。同じ時点で **970MB が既にスワップに出ていた**。

**詰まりの兆候が1回の測定で出た。** 上限128で同じ音声を2回流したとき、**出力は1文字も変わらないのに2回目は54%遅かった**（258秒 → 397秒）。遅くなったのは端末側である。

**速度と完全性が交換関係にある。** 上限128が速かったのは途中で打ち切っていたためで、切らずに出させると実時間比 3.89 になる。個別では **37.17秒の発話に148秒、35.48秒に166秒**。1発話ぶんでこれなので、次の発話は待ち行列に積まれる。

### 出力の途中切れ

**既定の `maxNewTokens` = 128 で切れる。** 上限を 512 に上げると **25件中6件の出力が変わった**（残り19件は128でも最後まで出ていた）。**切断は長い発話に限った話**であり、モデルの認識能力の不足ではない。

## 10. 出力の中身

**人の確認が要る。以下は判定ではなく観察である。**

### 表記（課題②）— 3候補で最も良い

同じ23.13秒の発話。

| | 出力 |
|---|---|
| NeMo | フェceブok … iphone … airdrop … itリテラシー |
| SenseVoice | フェイスブック … アイフォン … **エアジョロ** … アティイテラス |
| **Qwen3** | **Facebook … iPhone … AirDrop … Mac … Samsung … IT** |

同じ25件で `I think` がどう出たかを数えると:

| | 種類 | 中身 |
|---|---|---|
| NeMo | **5通り** | `ietin` / `ifteink` / `iceting` / `iiceting` / `アイス` |
| SenseVoice | **3通り** | `アインク` / `アイシンク` / `I think` |
| **Qwen3** | **2通り** | `I think`（6回） / `アイティン`（4回） |

**Qwen3 でも定まってはいない。** 発話をまたぐと英字とカタカナが入れ替わる。ただし**1つの発話の中では一貫**しており、NeMo のように語の途中で表記が切り替わる（`フェceブok`）ことはない。

### 現行が落としている節 — SenseVoice と同じ結論に独立に到達

| wav | NeMo（4回の流し直しすべて） | Qwen3 上限512 |
|---|---|---|
| 19-48-45（35.48秒） | …よく分からないんだけれども**〔無〕**例えば明治時代の… | …よくわからないだけれども、まあ**世界史についてはよく知っています。**例えば、明治時代の… |

**S6 で SenseVoice だけが出していた句を、系統の違う Qwen3 も出した。** 落ちている箇所が wav の端ではなく真ん中であることも確認済み。**ただし「実際に言ったか」は本人にしか判定できない**（`answers.tsv` の `answer` 列も録音時の NeMo 出力から作られているため、ラベル側にも答えが無い）。

### 英語・普通話 — S6 と同じ

- 34.65秒の英語: NeMo `そうシ` → Qwen3 は最後まで英語で出す（SenseVoice と同内容）
- 30.07秒の普通話: NeMo `オシーリベレン…` → Qwen3 `我是日本人，我的爱好是网球…`（SenseVoice と同内容）
- **`noise` と分類されていた 5.50秒・6.11秒も英語の発話だった**（S6 と同じ。区分が現行モデルの失敗を写している証拠が2つになった）

### 弱点

- **日本語の音声に中国語を返すことがある。** 30.52秒の発話 → `介绍。来。咱们。日本。的。留学生。的。梦想。的。日本`。0.61秒の発話 → `系统。` 自動判定の失敗
- **数字は直らない。** `千六百二年に、違うな、千六百年年に`（NeMo `162年`→`1600年`、SenseVoice `16002年`→`1600年`）。3候補とも外す
- 空の結果は 1件 → 2件 と**増えた**

## 11. 評価上の制限

- **上限512では同じ音声を2回流せていない。** 1回に28分かかり、runner のタイムアウト（40分）に2回目が入らなかった。**決定性の確認は上限128の結果（25/25一致）に依る**
- **上限128と上限512は別のインストールで測った。** ただし**両方で現行 NeMo が S4 と一致している**ので、比較の土台は揃っている
- **上流はモデルのチェックサムを公表していない**（§5）
- **正解が確定している行は3件しかない**（S3 からの持ち越し）。**これが全候補の比較の解像度を決めている**
- **`answers.tsv` の `category` は現行モデルの出力に引きずられている。** `noise` の一部が英語の発話である。**区分の付け直しが要る**
- **区分ごとの精度を人が判定していない。** `session_20260921_s7_long/review.tsv` の24行が `pending`

- **S8 `nemotron` は飛ばさない。** 日本語は落ちていない
- **課題②（表記）には、少なくとも1つ有効な手があると分かった。** Qwen3 は採れないが、**「多言語モデルなら英字が英字のまま出る」ことは実証された**。S8 で同じ点を見ること
