# 今後の調整候補

調査日: 2026-09-22。[入口](README.md)

**以下は実施済みの改善ではなく、症状に応じて選ぶ比較候補です。** SenseVoiceの採用をやり直すための必須ゲートではありません。現行のauto・ITN有効・1 thread・VAD一式を基準に、必要なものから1つずつ試します。

## 1. 優先順位

| 優先 | 気になる症状 | 最小の比較 | 分かること / 続ける条件 |
|---|---|---|---|
| A | `1600年 → 16002年`、数字や言い直しの誤り | 同一PCM・同一区間でITN on/off | 値・語・反復の差。特定例だけでなく既存の正常例も保てるか |
| A | 空白で読みづらい、検索に出ない | 現行検索と、日本語文字間の空白に寛容な検索 | 保存文を変えず検索漏れを直せるか。英文や複数キーワードを壊さないか |
| A（症状時） | 長文の後半欠落、表示待ちが長い | 実区間長を記録し、同一連続音の区切り方を比較 | 30秒超の区間・境界欠落・待ち時間との関係 |
| A（症状時） | 停止後・watchdog再始動後の最初の声が欠ける | 現行状態維持と、末尾回収後resetして再開 | VADの残存状態が影響するか。通常OS復帰とは分ける |
| B | 語頭・短い「はい」「うん」が欠ける | 現行0.35と0.5、必要なら短い前余白 | ASRへ渡す前に音が欠けているか。旧NeMo結果を再現扱いしない |
| B | 日本語なのに別言語として出る | 該当例だけauto/ja、英中の正常例も併走 | 言語条件の効果。通常のauto採用を崩す根拠があるか |
| B | 推論が遅い・待ちが溜まる | ASR threads 1/2 | 推論時間と全体待ちが改善するか。熱・電池とは分ける |
| C | 同じ音で同じ語を誤る | 同じ元モデルのFP32/int8 | 量子化の寄与。PCで差が薄ければ実機への大型モデル配置を急がない |
| C | 同じ用語の誤認が繰り返される | 少数の確定例に限定した辞書補正 | 誤置換が増えず役立つか。ネイティブhotwordとは区別 |
| D | 用語・日英表記を根本的に寄せたい | 日本語の追加学習、別デコーダの小規模調査 | 設定調整で届かない誤りが十分にある場合のみ |

根拠と版ごとの制約は [設定](model-and-settings.md)、[言語別の課題](languages.md)、[アプリ実装](app-best-practices.md) にあります。Aもすべて直ちに実施するという意味ではなく、数値や検索など既存の具体例から始めやすい候補です。

## 2. まず試すなら ITN と検索

### ITN: 新しい録音を大量に作る前に、既存音声で比べる

1. 既存S6音声のうち、数字、日本語中の英語、普通話、英語の代表例を使う。
2. モデル・PCM・区間・言語・threadsを同じにして、ITNだけを変える。
3. 生テキスト、token、言語ラベル、時間を並べ、差が出た例だけ読む。
4. 数値が良くなっても、節の欠落や英中の崩れが増えれば全体OFFにはしない。

v1.13.8 の SenseVoice は、streamの `use_itn` オプションを読むため、比較用には次の形も使えます。**提案例で、今回アプリには追加していません。** [native実装][impl]・[Dart stream API][stream]

```dart
// decode 前に設定。未指定なら recognizer の ITN 設定を使う。
stream.setOption(key: 'use_itn', value: '0'); // OFF。ON は '1'
```

言語指定に同じstream単位の切替を仮定しないこと。言語比較は設定の異なる認識器を順に作るほうが確実です。

### 検索: 音声を再認識しなくても比較できる

`徳川 家康`、`だっ たり`、正常な日本語、`machine learning`、型番、日英混在、空白で区切った複数検索語を少数の例として並べます。現行と提案のヒット結果を比べ、正しい一致が増えることと、意図しない一致を増やさないことを確認します。

表示の空白処理も導入するかは別判断にします。現行の「保存時に確定し、表示済み文をあとから変えない」という方針を保つなら、検索だけを改善する方法があります。

## 3. 比較の入口を間違えない

| 何を変えるか | 同じに保つもの | 適した入力 |
|---|---|---|
| ITN・言語・モデル・量子化 | PCMと区間境界 | 同じ切り出しをそのままASRへ渡す |
| VAD・前余白・区間上限 | 元の録音とチャンク供給条件 | **切り出し前の連続PCM** |
| 保存・検索の正規化 | 生の認識テキスト | テキストだけでも比較可能 |
| threads・待ち時間 | 端末、ビルド、音声、画面状態 | 同条件を複数回。初回ロードと通常推論を分離 |

[S5の教訓](../spike/segmentation.md) は、切り出し済みwavを再度VADに入れると、本番にはない語頭欠けを作ることです。旧実験の大きな改善率を、そのまま本番の期待値にしません。

また、録音時のFloat32と保存後のPCM16 wavでは丸めが入り、同じ録音でも完全に同じ入力とは限りません。録音時の結果と再生時の結果を直接A/Bにせず、**同じ保存音声を流し直した結果同士**で比べます。[既存baseline](../spike/current-baseline.md)

## 4. 残す記録と判断のしかた

大量の全件採点を依頼するより、既存の音声・正解を使い、差が出た例だけ確認する構成がmomeoの方針に合います。新しく残すなら、次の情報を一つの比較表に持たせます。

| 分類 | 記録項目 |
|---|---|
| 再現条件 | アプリcommit、runtime版、モデル/tokenのハッシュ、言語、ITN、threads、VAD値 |
| 入力 | 音声ID、サンプルレート、サンプル数、元録音内の開始終了sample、停止・再開イベント |
| 出力 | 生text、必要ならtokens/lang/event、空結果、native例外ログの有無 |
| 品質 | 語・節の欠落、数値、相づち、表記、検索の成否 |
| 速度 | 区間長、decode時間、処理待ち秒数、発話終了から保存まで |

日本語・中国語の内容比較には CER、英語には WER を使えます。ただし空白・句読点を除いた値だけでは、空白による検索漏れや数字の見え方を見落とします。生の結果も残し、内容と表示品質を分けます。漢字・かな・数字の正規化規則は先に固定し、都合のよい採点だけを選びません。

「同じ例が一度良くなった」だけでは採用しません。問題の例で改善があり、すでに通る日本語・英語・普通話・短い声を壊さないかを少数の既存例で見ます。必要な人の判断は、内容が合っているかと、本人がこの出方を使いたいかです。

## 5. 今回は結論が出ていないこと

- SenseVoiceで最適なVAD値、前余白、厳密な区間長。
- ITN OFFが日本語の数字・固有名詞を改善するか。
- int8をやめると本人の誤認が減るか。
- 1→2 threadsがiPhone/Pixelの電池・熱まで改善するか。
- VADの状態持ち越しが実際に再開時の欠けを起こしているか。
- 日英の固有名詞に効く、小容量で運用可能な日本語追加学習レシピ。

いずれも「設定を変えれば直る」とはまだ言えません。症状と入力を残せたものから、表の最小比較へ進めます。
