# これから何を、どの順番でやるか

> **状態（2026-09-21）**: **洗い出しの文書である。まだ何も実装していない。**
> 採用の決定そのものは [adopt-sensevoice.md](adopt-sensevoice.md) にある。本書はその先の段取りを並べる。
> 本書を書くにあたって、`main` の実装を実際に読んで確かめた。**記録からの引き写しではない箇所には「コード確認」と書く。**

## この文書の使い方

**3つに分けて並べる。**

1. **SenseVoice に差し替えるために必要なこと** — 何が NeMo 専用で、何がそうでないか
2. **SenseVoice 以外に残っている改善** — 差し替えと独立に効くもの
3. **順番** — どれを先にやるか、なぜその順か

**方針**: **基本の部分だけを作り切る。** 出力の加工・設定値の調整・体験の作り込みは入れない（§2-3）。**測定のゲートも置かない**（§2-2）。作り切ってから、本人が普段どおり使って判断する。

## 第1部. SenseVoice に差し替えるために必要なこと

### 1-1. 先に結論 — 「全部が NeMo 専用」ではなかった

**心配していたほど絡んでいない。** 音を取る側（録音・VAD・区切り）は**モデルに依存していない**。


| 層                      | NeMo 専用か           | 理由                              |
| ---------------------- | ------------------ | ------------------------------- |
| 録音（16kHz・PCM16）        | **依存しない**          | sherpa の入力形式であってモデルの都合ではない      |
| VAD（silero・区切り設定）      | **依存しない**          | 別のモデル（`silero_vad.onnx`）が担当している |
| 認識器の生成                 | **依存する**           | sherpa の設定の枠が違う。**ただし15行**      |
| モデルの住所を返す窓口            | **名前だけ依存**         | 構造は「2ファイルのパス＋バイト数検証」で汎用         |
| 配布（iOS 同梱・Android パック） | **依存する**           | ここが一番重い                         |
| 出力を受け取る側               | **依存しない。が、出力が変わる** | この計画では加工せず、そのまま出す               |


### 1-2. NeMo 専用になっている箇所（コード確認）

`main` で NeMo に触れているのは **18ファイル**である。大半は名前と文言で、設計を変える必要はない。


| 場所                                                   | いまの状態                                            | やること                                              | 重さ      |
| ---------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------- | ------- |
| `lib/stt/stt_audio_worker.dart`                      | `nemoCtc:` の枠にパスを入れている                           | `senseVoice:` の枠へ。言語 `auto`、ITN 有効                | **15行** |
| `lib/stt/stt_model_provisioner.dart`                 | `nemoModel` / `nemoTokens` / `_resolveNemoPaths` | 名前を汎用化。構造は変えない                                    | 小       |
| `scripts/lib/nemo_model_constants.sh`                | `655542604`                                      | `239233841` **へ。1か所に寄せる**                         | 小       |
| `lib/providers/stt_providers.dart`                   | `_isNemoReady` と文言                               | 同上                                                | 小       |
| `scripts/download_nemo_model.sh`                     | NeMo の URL と SHA                                 | SenseVoice へ。`setup_sensevoice.sh` **に検証済みの値がある** | 小       |
| `scripts/place_ios_models.sh` / `place_android_*.sh` | NeMo を配る                                         | 参照するファイルを替える                                      | 小       |
| `Makefile`                                           | `make models` が NeMo を取る                         | 同上                                                | 小       |
| `.gitignore`                                         | NeMo の実体を除外                                      | パスが同じなら変更不要                                       | なし      |
| dev カタログの表示                                          | 「NeMo 本体」等                                       | 文言                                                | 小       |


**バイト数が二重管理になっている。** `scripts/lib/nemo_model_constants.sh` と `lib/stt/stt_model_provisioner.dart` の両方に同じ数字がある。コメントに「更新時は両方直すこと」と書いてあるが、**差し替えのついでに片方へ寄せる**ほうが安全である。

### 1-3. 配布 — ここが本丸。ただし軽くなる

**モデルが 655MB → 239MB（-64%）になる。** 差し替えの副次的な利得として大きい。


|             | いまの状態                                  | やること                                                                                 |
| ----------- | -------------------------------------- | ------------------------------------------------------------------------------------ |
| **iOS**     | アプリ同梱（`SttModelChannel.swift` が固定名で参照） | **変更不要。** SenseVoice のファイル名が NeMo と同じなので、同梱の枠にそのまま入る（2026-09-21 に実機で確認）              |
| **Android** | fast-follow パック `nemo_models`          | **パック名を決める。** Dart・`settings.gradle.kts`・`app/build.gradle.kts` の**3箇所で一致**している必要がある |
| **取得**      | `download_nemo_model.sh`               | URL と SHA256 を差し替える                                                                  |


**iOS の release アプリは 287.3MB になった**（NeMo 同梱なら 790MB 相当）。

### 1-4. 出力は加工しない（この計画では触らない）

**認識テキストは、いま何の加工もされずにカードへ入っている。** 

`_onTranscribed` が `trim()` するだけで、そのまま DB に保存される（`lib/providers/listening_providers.dart:482`、コード確認）。

**この形のまま SenseVoice に替える。** 後処理は入れない。

替えると文字列の性質が変わることは分かっている。**直すかどうかは、使いながら決める**（§2-3 に残す）。


| 変化             | この計画での扱い                                                |
| -------------- | ------------------------------------------------------- |
| 句読点が付く（ITN 有効） | **そのまま出す**                                              |
| 不自然な空白が入る      | **そのまま出す**                                              |
| 英語がカタカナになる     | **判断済み**（[adopt-sensevoice.md](adopt-sensevoice.md) §2） |
| 数字は直らない        | `1600年` → `16002年`。現行も `162年` で誤り。**どちらも直らない**          |


**後処理を入れる場所だけ決まっている。** 表示済みのテキストを書き換えないのが前提条件なので、置けるのは `_onTranscribed` の中、`_repository.insert` より手前だけである。

### 1-5. 現行の値をそのまま使う（ただし根拠は現行モデルの上のもの）

**設定値は動かさない。** ただし、**これらの値の根拠はすべて現行モデルの上で測ったもの**であることを記録しておく。SenseVoice で最適である確認はしていない。


| 項目                  | いまの値     | 根拠の限界                                       |
| ------------------- | -------- | ------------------------------------------- |
| `numThreads`        | 1        | S6 も1スレッドで測った。他の値は試していない                    |
| `maxSpeechDuration` | 30.0秒    | **SenseVoice は非ストリーミング型**である。長い発話での挙動は見ていない |
| `threshold`         | 0.35 にする | 効果は**現行モデルの上でしか測っていない**                     |
| 前余白                 | 追加しない    | `threshold` と重複するという判断も、現行モデルの上での話          |


**使っていて長い発話が崩れるようなら、**`maxSpeechDuration` **がいちばん疑わしい。** そのときに触る。

## 第2部. SenseVoice 以外に残っている改善



### 2-1. いますぐ入れられるもの（モデルと独立）


|     | 変更                                   | 根拠                                | 期待してはいけないこと                      |
| --- | ------------------------------------ | --------------------------------- | -------------------------------- |
| 1   | `sherpa_onnx` **を 1.13.8 にする**       | 追随コストゼロ。**全 spike がこの上で測られている**   | **精度は上がらない。** 空も崩壊も減らない          |
| 2   | **VAD に** `threshold = 0.35` **を渡す** | 連続音で空 1件 → 0件、相づち 10件 → 11件、副作用なし | **読みやすさは変わらない。** 本人の読み比べで差が出なかった |


**どちらも** `main` **にまだ入っていない**（コード確認）。

- `pubspec.lock` は **1.13.3 に固定されている**。`ios/Podfile.lock` も同様だった（2026-09-21 に spike ブランチ側で 1.13.8 へ更新済み）
- `threshold` **は** `lib/` **のどこにも現れない。** sherpa の既定 0.5 で動いている

**この2つは同時に入れる。** 別々に入れると、本番の土台が測った条件のどれとも一致しなくなる。

`0.25` **まで下げない。** 物音を1件余計に拾い、空が1件増える。**0.35 で止める。**

### 2-2. 測らないと決めたもの

**最後まで作り切って、本人が普段どおり使って判断する。** 測定を先に挟まない。


| 項目               | 扱い                                    |
| ---------------- | ------------------------------------- |
| **電池と発熱**（S1 段C） | **実施しない。** 段A・段Bで内訳は出ている。異常は日常の使用で気づく |
| **常時録音・長時間**     | **測らない。** そのまま使うことが評価そのものになる          |
| **台本コーパスの逐語採点**  | **実施しない。** 読みやすさは本人が読めば分かる            |
| **iOS の RAM**    | **測らない。** 落ちたら分かる                     |


**理由**: 測定は本人の手数を増やす。**使い勝手は使えば分かる**ものであり、そこに測定を挟むと、判断が出るまでの時間だけが伸びる。

**測るのは、使っていて次のどれかが起きたときだけである。**


| 起きたこと              | そのとき測るもの                                        |
| ------------------ | ----------------------------------------------- |
| 電池の減りが明らかに速い、端末が熱い | S1 段C（`scripts/measure_spike_power.py` がある）     |
| アプリが勝手に落ちる・録音が止まる  | RAM。**体感では原因が分からない唯一の種類**                       |
| 文字が明らかに悪くなった気がする   | 台本コーパスで採点（`scripts/score_script_corpus.py` がある） |


**道具は全部そろっている。** 引き金を引いたときにだけ使う。

### 2-3. この計画から外したもの（使いながら調整する）

**基本の部分を先に整える。体験と精度の調整はそのあとにする。** 分かっていることだけ書き留めておく。


| 項目              | 分かっていること                                                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **語中の空白**       | `それ に比較して、徳川 家康だっ たりとか。` の `徳川 家康` は、**検索で「徳川家康」と打ってもヒットしない**。検索語は空白で分割され、本文側の空白は消されない（`lib/pages/listening/memo_keyword_filter.dart`、コード確認） |
| **文の切れ目としての空白** | `いろいろ言ってみるよ 僕は日本史について` の空白は切れ目である。**機械的に詰めると繋がって読みにくくなる。** 語中のゴミと切れ目は形の上では区別できない                                                             |
| **末尾の** `。`     | カードは発話ごとに空行で区切って追記するため、行末に `。` が並ぶ。現行は付いたり付かなかったり（実測28行中9行）、SenseVoice は一貫して付く                                                               |
| **過去のカードとの混在**  | 表示済みは書き換えないので、**句読点のあるカードと無いカードが一覧に混ざる。** これは直せない                                                                                            |
| **設定値の微調整**     | `numThreads`・`maxSpeechDuration`・前余白（§1-5）                                                                                                   |


**空白の2件だけ、性質が違う。** 使っていても気づきにくい（検索が静かに外れるだけ）。**ほかは使えばすぐ分かる。**

### 2-4. 解けないと認めるもの

**課題②（日本語の文中に混ざる英単語を、英字のまま出す）は、いまの条件では解けない。**

英字で出せたのは Qwen3 だけで、その Qwen3 は常駐 RAM 4,010MB で積めない。置換辞書はキーが安定せず届かない。SenseVoice と Nemotron はカタカナに倒れる。**「まだ調べ足りない」ではなく、現時点の結論として書き残す。**

**条件が変わったら見直す。** 端末の RAM が増えるか、Qwen3 の軽量版が出たときである。

### 2-5. 着手しないもの

- **課題④（自分と他人の声の識別）** — ①〜③の結論が出るまで切らない方針。順番が回ってきていない
- **S9** `hotwords` — Qwen3 の不採用に伴って終了
- **S10 表記の置換辞書** — 材料が2件で互いに逆を向いている

## 第3部. 順番

**基本の部分だけを、最後まで作り切る。** 出力の加工も設定値の調整も入れない。**途中に測定のゲートも置かない。**

**そのうえで普段どおり使い、体験と精度の調整はそのあとで決める**（§2-3）。

### 第0段 — 土台（モデルと独立）

`sherpa_onnx` **1.13.8 ＋ VAD** `threshold = 0.35`**。**

**なぜ先か**: モデル差し替えと独立していて、**単独で戻せる**。`threshold` の1行だけ戻す、という対処ができる状態を先に作る。

### 第1段 — モデルの差し替え

**認識器・住所を返す窓口・取得スクリプト・定数。**

認識器の枠を `nemoCtc` から `senseVoice` へ替え、`nemoModel` / `_resolveNemoPaths` などの名前を汎用化し、バイト数の二重管理を1か所へ寄せる。

### 第2段 — 配布

**Android の fast-follow パック、iOS の同梱、スクリプトと Makefile。**

**fast-follow は残す。** パックは「決まった名前の2ファイルを入れる箱」でしかなく、SenseVoice もファイル名が同じなので**箱も配置スクリプトもそのまま使える**。替えるのは取得元（URL と SHA256）とバイト数だけである。

- **パック名** `nemo_models` **は替えなくても動く。** ただし名前が実態と合わなくなる
- **替えるならリリース前にする。** 出したあとでパック名を変えると、既存インストールの扱いが別物になる
- **ベースに同梱できるかは測っていない。** 見積もりでは 198.6 MiB で、200 の解釈次第という境界線上だった（[fast-follow が要るか](#補足-fast-follow-をやめられる可能性)）



### そして — 普段どおり使う

**これが判断の場である。** 電池の持ち、発熱、カードの読みやすさ、相づちの拾い方、句読点の見え方。**全部、使っていれば分かる。**

**やめる判断もここで出す。** 使ってみて現行のほうが良ければ、第0段の状態へ戻す。**戻し方は各段に書いてある。**

## 補足. fast-follow をやめられる可能性

**いまは残すと決めた。** ただし、やめられる可能性があることは記録しておく。

`notes/on_device_stt/model_distribution.md` §6-2 が、この状況を先に書いていた。

> もし軽量モデルに替えてアプリ全体が200MB以下に収まれば、Android も普通のアセット同梱で済み、**PAD は不要になる**。そのとき iOS/Android の実装差はほぼ消える。

**測った見積もり**（2026-09-21）。


|                                | サイズ                          |
| ------------------------------ | ---------------------------- |
| SenseVoice モデル（gzip -6）        | 152.7 MiB                    |
| アプリ本体（arm64 release APK・モデル抜き） | 45.9 MiB                     |
| **合計**                         | **198.6 MiB ／ 208.3 MB（十進）** |


**200 MiB なら 1.4 MiB の余裕で入り、200 MB（十進）なら 8.3 MB 超える。** 見積もりでは判定できない。

**やめられた場合に消えるもの**: `android/nemo_models/` の gradle モジュール、`AssetPackDelivery`、準備ゲートの `downloading` / `almostThere` フェーズ、DL完了待ちとその再試行。**iOS と Android が同じ配布方式になる。**

**判定したくなったときは** `bundletool get-size total` で AAB を1本測れば分かる。**いまはやらない。**
