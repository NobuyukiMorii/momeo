# 採用判断 — SenseVoice Small に差し替える

> **状態（2026-09-21）**: **SenseVoice Small int8（2024-07-17）を採ると決めた。**
> 決め手は**実アプリに入れて本人が使った感触**である。逐語の採点ではない。
> 実験コードはブランチ `spike/voice_recognition_performance_tuning/sensevoice` にある。**`main` にはマージしない。**

## 結論

**現行の NeMo CTC 0.6B をやめ、SenseVoice Small int8 に差し替える。**

固定 wav の比較（S6）で有力候補だったものを、**本番と同じ経路（マイク → VAD → 認識 → カード表示）に載せて Android と iPhone の両方で動かした。** 本人が使ったうえで、採ると判断した。

| | 現行 NeMo | SenseVoice |
|---|---|---|
| モデル本体 | 655,542,604 バイト | **239,233,841 バイト** |
| 常駐 RAM（実アプリ・Android） | — | **691MB** |
| 常駐 RAM（固定 wav アプリ・S6 実測） | 1,393MB | 778MB |
| エンジン読み込み | — | 1,504ms |
| 日本語で落ちる節 | **ある**（本人確認済み） | 出る |
| 英語・普通話 | 読める文字にならない | 出る |
| 日本語中の英語 | 表記が実行ごとに揺れる | **カタカナに固定される** |

**RAM とモデルサイズが半分以下になる。** 精度を上げるために重くなる、という交換ではなかった。

## 1. 決め手

**本人の評価**（2026-09-21・実機）。

- 「とんでもなく精度が上がった気がします」
- 「サクサク動いて問題ありません」

**これは測定ではない。** 体感である。ただし**体感と、S6 で測った事実が同じ方向を向いている**。

- S6 で、現行が落としていた「世界史についてはよく知っています」「表現方法が少し違いますと」を SenseVoice が出した（[spike/sensevoice.md](../spike/sensevoice.md) §4）
- 本人がこの2箇所を**実際に話したと確認している**
- 同じ箇所を Qwen3 と Nemotron も出した（[spike/qwen3.md](../spike/qwen3.md)、[spike/nemotron.md](../spike/nemotron.md) §6.2）

**現行の出力が自然に読めることは、内容を取りこぼしていない保証にならない。** これが差し替えの中心的な理由である。

## 2. ここで解けた「人にしか決められない判断」

[spike/sensevoice.md](../spike/sensevoice.md) は、人が判断しないと採否が決まらない点を3つ挙げていた。そのうち**1つが、この検証で解けた**。

| 判断 | 状態 |
|---|---|
| **日本語中の英語がカタカナになるのを受け入れるか** | **受け入れる**（本人が実アプリで使って判断） |
| 現行が落とした節を本当に言ったか | 確認済み（S7・S8 の記録） |
| 英語・普通話の正解 | 未確定。採用判断には使っていない |

**カタカナ受容が採否の分かれ目だった。** `ITリテラシー` が `アイティイテラス` になり、`airdrop` が `エアジョロ` になる。ラテン文字表記そのものは失われる。**それでも、読める日本語が増えるほうを採る。**

`review.tsv` の行を読み比べる方法では決まらなかった。**自分のアプリで自分の声を見るほうが早かった。**

## 3. 経緯

| 時点 | 何をしたか |
|---|---|
| S6 | 固定 wav の無音評価で SenseVoice を測り、「有力候補」まで進めた。**マイクは通していない** |
| S7・S8 | Qwen3 は常駐 RAM 4,010MB で条件外、Nemotron は相づちが 0/9 で失格 |
| 台本コーパス | S6 のあとに録ったため、**SenseVoice だけ逐語の採点がない**状態が残った |
| 2026-09-21 | **本番の起動経路に SenseVoice を載せ、Android と iPhone で動かした** |

**S6 が測ったのは固定 wav 専用アプリだった。** 常駐通知も画面も DB も無い条件である。今回はじめて、実アプリの条件で動いた。

### 今回やったこと

起動時に `--dart-define=STT_MODEL=sensevoice` を見て、認識器を切り替える。**指定が無ければ従来どおり NeMo で起動する。**

| 端末 | 結果 |
|---|---|
| Pixel 8a（Android 17） | 動作。debug ビルド。手置きしたモデルを読む |
| MoryPhone（iOS 26.6.2） | 動作。release ビルド。アプリに同梱 |

**iOS で動かしたのは、この一連の spike で初めてである。** これまでの S3〜S8 はすべて Android の `adb` 経由だった。

**iOS への同梱は、Xcode の登録を変えずに済んだ。** SenseVoice のファイル名が NeMo と同じ（`model.int8.onnx` / `tokens.txt`）なので、同梱の枠にそのまま入る。iOS の release アプリは 287.3MB になった。

**`ios/Podfile.lock` が sherpa_onnx_ios 1.13.3 のままだったことが、ここで分かった。** iOS をビルドしたのが今日はじめてだったためである。1.13.8 に更新した。**全 spike は 1.13.8 の上で測られているので、iOS だけ 1.13.3 に残すと土台が違う。**

## 4. まだ決まっていないこと

**この判断は「モデルを差し替える」ところまでである。** 次は本番条件で落ちないかを見る段になる。

| 残っていること | なぜ残っているか |
|---|---|
| **電池と発熱** | 本人が挙げた採用条件だが、一度も測っていない（S1 段C） |
| **長時間・常時録音** | 全 spike が固定 wav か短時間の試用。待ち行列と画面OFFは未評価 |
| **台本コーパスでの逐語採点** | SenseVoice だけ採点がない。Nemotron は 75.0% / 現行 70.2% まで出ている |
| **iOS の RAM** | 691MB は Android の数字。iOS はメモリの打ち切りが機種依存で厳しい |
| **句読点と空白の後処理** | SenseVoice は句読点を出し、`徳川 家康だっ たりとか。` のような空白も入れる |
| **Android の本番配信** | fast-follow パックは NeMo 向けのまま。差し替えていない |

**ここで落ちたら、この判断に戻る。**

## 5. 数字の確度

**本書の数字は、測り方が揃っていない。**

- **691MB は起動直後の1点**である。S6 の 778MB は約2秒ごとの観測最大で、条件が違う。**同じ土俵の比較ではない**
- **1,504ms は debug ビルド**の値である。release は AOT なので速い
- **精度は測っていない。** 本人の体感だけである

**「半分以下になった」は言えるが、「何%速くなった」は言えない。**

## 6. 後続への申し送り

### 確定したこと

- **SenseVoice Small int8（2024-07-17）を採る**
- **言語は `auto`、ITN 有効、ASR 1スレッド**（S6 で採った条件。`ja` 固定は普通話を壊し、日本語側の利得も無い）
- **sherpa_onnx は 1.13.8 に揃える**（iOS の Podfile.lock を含む）
- **VAD の `threshold` は 0.5 → 0.35**（[spike/segmentation.md](../spike/segmentation.md)）
- **Qwen3・Nemotron は候補から外す**

### 実装へ渡すこと

- **モデルの住所を返す窓口が NeMo 専用の名前のままである。** `nemoModel` / `nemoTokens` / `_resolveNemoPaths` など。構造は「2ファイルのパス＋バイト数検証」で汎用なので、名前と定数の付け替えで足りる
- **バイト数が二重管理になっている。** `scripts/lib/nemo_model_constants.sh` と `lib/stt/stt_model_provisioner.dart` の両方。差し替えのついでに1か所へ寄せる
- **Android のパック名 `nemo_models` は Dart・`settings.gradle.kts`・`app/build.gradle.kts` の3箇所で一致している必要がある**
