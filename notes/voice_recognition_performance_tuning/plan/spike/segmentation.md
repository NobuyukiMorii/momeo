# S5 `segmentation` — 区切り設定だけを振る

## 1. このセッションへの指示

- このセッションでやるのは **S5 だけ**。モデルは**現行のまま**、ライブラリは**1.13.8 のまま**にする。
- 変えるのは**発話の区切りに関する設定だけ**。1つずつ振る。
- S2 `capture-audit` と S3 `current-baseline` の記録が**必須**。無ければ**進まずに止まる**。
- 「長くまとめれば文脈が増えて精度が上がる」という前提で設計しない。**区間を長くすることと、モデルが見る文脈が広がることは別**である。ここでは探索項目として振るだけ。
- 結果は `notes/voice_recognition_performance_tuning/spike/segmentation.md` に書く。**`main` にはマージしない。**

## 2. 背景

### 仮説

無音しきい値や前後の余白を変えると、**モデルを替えずに**日本語の取りこぼしが減る。

### 答える問い

- S2 で見つかった欠け（語頭・語尾・相づち・停止時の端数）は、設定を変えると減るか
- 減らす代わりに、区切りが粗くなって読みにくくならないか
- 重複認識や文字の二重追加が起きないか

### 触る対象

`lib/stt/stt_audio_worker.dart` の先頭にある定数。

| 定数 | 現在値 | 意味 |
|---|---|---|
| `_kMinSilenceDuration` | 1.5 | 無音がこれだけ続いたら発話終了とみなす |
| `_kMinSpeechDuration` | 0.25 | これより短い音は発話とみなさない |
| `_kMaxSpeechDuration` | 30.0 | 1発話の上限 |
| `_kVadWindow` | 512 | VAD に1回で渡すサンプル数 |

加えて `_AudioEngine.stopListening` は、変換バッファ `_floatBuffer` の残り（512未満 ≒ 最大32ms）を VAD に投入していない。**S2 でここが語尾を削っていたなら、投入する変更もこの spike の候補に入る。**

> `sherpa_onnx` の VAD 設定（`SileroVadModelConfig`）には、上の3つのほかに設定項目がある可能性がある。**想像で名前を書かない。着手時に `~/.pub-cache/hosted/pub.dev/sherpa_onnx-1.13.8/lib/src/vad.dart` を開いて実際の項目を確認すること。**

## 3. 開始条件と依存

- ブランチ: `main` から `spike/voice_recognition_performance_tuning/segmentation` を切り、**`sherpa_onnx` を 1.13.8 にした状態**から始める（S4 と同じ版に揃える）
- **依存: S2 と S3 が完了していること**
  - `spike/capture-audit.md`（どこが欠けていたか）
  - `spike/current-baseline.md`（比較の基準と音声）
  - **どちらか欠けていたら、このセッションはここで止める**
- S2 で境界の問題が見つかっていなければ、**この spike は後回しにしてよい**。その判断も記録に書く

## 4. 作業の分担

| 誰が | 何を |
|---|---|
| エージェント | ブランチ作成、設定を振る仕組みの用意、固定音声での実行、結果の突き合わせ、記録の下書き |
| **人** | 実機への再インストール、実機の操作、**読みやすさの判断（区切りが粗くなっていないか）** |
| 止まる条件 | 読みやすさの判断が要るところ。数値では決められないため人に聞く |

## 5. エージェントが行う手順

1. ブランチを切り、`sherpa_onnx` を 1.13.8 にする。
2. S2・S3 の記録があることを確認する。**無ければ止める。**
3. S3 で作った「固定 wav を流す dev 経路」を用意する。**VAD 経由の経路**を使う（丸ごと経路では区切りを評価できない）。
4. **設定を1つずつ振る。** 一度に複数を動かさない。振る順は、S2 で見つかった欠けに効きそうなものから。
   - 語尾が欠けている → まず `stopListening` の端数を投入する変更、次に `_kMinSilenceDuration`
   - 相づちが落ちている → `_kMinSpeechDuration`
   - 長い発話が途中で切れる → `_kMaxSpeechDuration`
5. 各設定について、S3 の**調整用**音声を流し、出力をファイルに書き出す。**最終判定用はまだ使わない。**
6. 良さそうな設定が決まったら、最後に**最終判定用**で確かめる。
7. 人に §6 を依頼し、読みやすさの判断を受け取る。

## 6. 人が行う手順

- 実機への再インストールの承認と操作
- 設定ごとの出力を読み、次を返す

| 返してほしいもの | 形 |
|---|---|
| 読みやすさ | 元の設定と比べて、読み返しやすくなったか・粗くなったか |
| 区切りの位置 | 文の途中で切れていないか、逆にくっつきすぎていないか |
| 気になった事例 | 実際の出力を引用して |

|---|---|---|---|---|
| 既定（基準） | 1.5 / 0.25 / 30.0 | | | |
| | | | | |

あわせて次を文章で残す。

- **どの設定が、どの欠けに効いたか**
- 効いた代わりに悪くなったこと

## 8. やらないこと

- モデルの差し替え
- ライブラリの版を 1.13.8 から動かすこと
- 「ひと続きの話をまとめて認識する」仕組みの作り込み（区間を長くする設計は、効果が確かめられてから別途考える）
- 本番の保存・画面・カードの作り方への変更

## 9. 完了条件と、次へ渡すもの

**完了条件**: 「区切り設定を変えると取りこぼしが減るか」について、**効いた設定か、効かなかったという事実**が記録に残っていること。

**次へ渡すもの**: `spike/segmentation.md` のみ。**コードはマージしない。**

効く設定が見つかった場合は、**以後のモデル比較（S6〜S8）でも同じ設定に固定する**。その設定値を記録の冒頭に明記しておく。
