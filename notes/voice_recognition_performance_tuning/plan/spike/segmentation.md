# S5 `segmentation` — 区切り設定だけを振る

## 1. このセッションへの指示

- このセッションでやるのは **S5 だけ**。モデルは**現行のまま**、ライブラリは**1.13.8 のまま**にする。
- 変えるのは**発話の区切りに関する設定だけ**。1つずつ振る。
- S2 `capture-audit` と S3 `current-baseline` の記録が**必須**。無ければ**進まずに止まる**。
- 「長くまとめれば文脈が増えて精度が上がる」という前提で設計しない。**区間を長くすることと、モデルが見る文脈が広がることは別**である。ここでは探索項目として振るだけ。
- **人の手数を増やす作りにしない**（`master.md` §1 の原則）。とくに次をさせない。
  - **設定を変えるたびに再インストールさせない。** 定数を書き換えて焼き直す作りでは、条件の数だけ人が実機を触ることになる。**設定は dev 画面から変えられるようにし、1回のインストールで全条件を回す**
  - **全件の出力を読ませない。** 設定間で差が出た行だけを見せる
  - 読みやすさの判断は**画面かファイルに書いてもらう**。チャットで返させない
- 結果は `notes/voice_recognition_performance_tuning/spike/segmentation.md` に書く。**`main` にはマージしない。**

## 2. 背景

### 仮説

無音しきい値や前後の余白を変えると、**モデルを替えずに**日本語の取りこぼしが減る。

### 答える問い

- S2 で見つかった欠け（語頭・語尾・相づち・停止時の端数）は、設定を変えると減るか
- 減らす代わりに、区切りが粗くなって読みにくくならないか
- 重複認識や文字の二重追加が起きないか
- **`_kMaxSpeechDuration` が上限として効いていないのはなぜか。効かせると何が変わるか**

### S3 から分かっていること（この spike が引き取る2件）

- **`_kMaxSpeechDuration`（30.0 秒）が上限として効いていない。** 33.56 秒・35.48 秒・37.17 秒の区切りが実際に出た。**設定を振る前に、まずこれを調べる。**「設定が効かない」状態で他の値を振っても意味がない
- **一度区切った wav を VAD に流し直すと、さらに細かく割れる**（24件 → 31区切り）。切り出した音の端に無音が残るためと考えられる。**固定 wav の「VAD 経由」経路で評価するときは、この二重区切りを差と取り違えない**

### 触る対象

`lib/stt/stt_audio_worker.dart` の先頭にある定数。

| 定数 | 現在値 | 意味 |
|---|---|---|
| `_kMinSilenceDuration` | 1.5 | 無音がこれだけ続いたら発話終了とみなす |
| `_kMinSpeechDuration` | 0.25 | これより短い音は発話とみなさない |
| `_kMaxSpeechDuration` | 30.0 | 1発話の上限（**効いていない。まず原因を見る**） |
| `_kVadWindow` | 512 | VAD に1回で渡すサンプル数 |

加えて `_AudioEngine.stopListening` は、変換バッファ `_floatBuffer` の残り（512未満 ≒ 最大32ms）を VAD に投入していない。**S2 でここが語尾を削っていたなら、投入する変更もこの spike の候補に入る。**

> `sherpa_onnx` の VAD 設定（`SileroVadModelConfig`）には、上の3つのほかに設定項目がある可能性がある。**想像で名前を書かない。着手時に `~/.pub-cache/hosted/pub.dev/sherpa_onnx-1.13.8/lib/src/vad.dart` を開いて実際の項目を確認すること。**

## 3. 開始条件と依存

- ブランチ: **S4 `lib-update` のブランチから枝を切る**（足場と 1.13.8 が揃っているため）。名前は `spike/voice_recognition_performance_tuning/segmentation`。**足場を作り直さない**（`master.md` §1）
- **依存: S2 と S3 が完了していること**
  - `spike/capture-audit.md`（どこが欠けていたか）
  - `spike/current-baseline.md`（比較の基準と音声）
  - **どちらか欠けていたら、このセッションはここで止める**
- S2 で入れた**生 PCM の保存と対応区間の切り出し**が要る場合は、S2 のブランチから取り込む（作り直さない）
- 前提: **Android 実機**（`master.md` §1）
- S2 で境界の問題が見つかっていなければ、**設定を振る部分は後回しにしてよい**。ただし **`_kMaxSpeechDuration` が効いていない件は S2 の結果と無関係に扱う**。その判断も記録に書く

### 先に済ませておくこと

**`最終判定用` の音声が未収録である**（S3 の残タスク）。この spike は「調整用で振って、最後に最終判定用で確かめる」という組み立てなので、**確かめる音声が無い**。

1. 設定を振り始める前に、人に**短く最終判定用を録り足してもらう**（いつも通り喋り、dev カタログ「STT → 録り込み」で用途を `最終判定用` に変えるだけ）
2. 録り足せない場合は、**調整用だけで判断したことを記録に明記する**

## 4. 作業の分担

| 誰が | 何を |
|---|---|
| エージェント | 枝の作成、**設定を dev 画面から振れるようにする**、固定音声での実行、差分の抽出、記録の下書き |
| **人** | 最終判定用の録り足し、実機への再インストール（**1回だけ**）、**読みやすさの判断** |
| 止まる条件 | 読みやすさの判断が要るところ。数値では決められないため人に聞く |

## 5. エージェントが行う手順

1. S4 のブランチから枝を切る（`sherpa_onnx` は 1.13.8 のまま）。
2. S2・S3 の記録があることを確認する。**無ければ止める。**
3. **`_kMaxSpeechDuration` が効いていない原因を先に調べる。** 37.17 秒の区切りが出るのは、設定が VAD に渡っていないのか、渡っているが別の条件で切れているのか、`sherpa_onnx` 側の扱いが想定と違うのか。**ここが分からないまま他の値を振らない。**
4. **設定を dev 画面から振れるようにする。** 定数を直接書き換えて焼き直す作りにしない。
   - 「STT → 固定 wav」の VAD 経由の経路に、無音しきい値・最短発話・上限などの入力を足す
   - **1回のインストールで全条件を回せる**状態にする。人が実機を触るのは最初の1回だけ
   - 設定値は結果 TSV の注記行に書き出す。**どの値で出た結果か、後から必ず分かるようにする**
5. **設定を1つずつ振る。** 一度に複数を動かさない。振る順は、S2 で見つかった欠けに効きそうなものから。
   - 語尾が欠けている → まず `stopListening` の端数を投入する変更、次に `_kMinSilenceDuration`
   - 相づちが落ちている → `_kMinSpeechDuration`
   - 長い発話が途中で切れる／上限を超える → `_kMaxSpeechDuration`
6. 各設定について、S3 の**調整用**音声を流し、出力をファイルに書き出す。**最終判定用はまだ使わない。**
   - **二重区切りに注意する。** 録り込んだ wav はすでに VAD で切られているため、VAD 経由で流すとさらに割れる（S3: 24件 → 31区切り）。**設定の効果と、この二重区切りを混同しない**
7. 既定の設定の結果と突き合わせ、**差が出た行だけを抽出する**。
8. 良さそうな設定が決まったら、最後に**最終判定用**で確かめる（録り足せた場合）。
9. 人に §6 を依頼し、読みやすさの判断を受け取る。

## 6. 人が行う手順

1. **最終判定用の音声を録り足す。** いつも通り喋り、dev カタログ「STT → 録り込み」で用途を `最終判定用` に変えるだけ（数件でよい）
2. 実機への再インストールの承認と操作（**この spike では1回だけ**）
3. **差が出た行だけ**を渡されるので、それを読んで次を返す

| 返してほしいもの | 形 |
|---|---|
| 読みやすさ | 元の設定と比べて、読み返しやすくなったか・粗くなったか |
| 区切りの位置 | 文の途中で切れていないか、逆にくっつきすぎていないか |
| 気になった事例 | 実際の出力を引用して |

**全件を読む必要はない。** 設定間で出力が変わらなかったものは渡されない。

## 8. やらないこと

- モデルの差し替え
- ライブラリの版を 1.13.8 から動かすこと
- 「ひと続きの話をまとめて認識する」仕組みの作り込み（区間を長くする設計は、効果が確かめられてから別途考える）
- 本番の保存・画面・カードの作り方への変更
- **設定を変えるたびに再ビルド・再インストールを繰り返すこと**
- 二重区切り（録り込み済みの wav をさらに VAD に通すことで生じる分割）を、設定の効果と混同すること
