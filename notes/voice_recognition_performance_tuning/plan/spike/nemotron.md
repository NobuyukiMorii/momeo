# S8 `nemotron` — Nemotron 3.5 に差し替えて比べる

## 1. このセッションへの指示

- このセッションでやるのは **S8 だけ**。
- **まず飛ばす条件を確認する。** S6 `sensevoice` と S7 `qwen3` の**両方で日本語が明確に落ちていたら、この spike は実施しない。** その判断を記録に書いて終わる。
- この候補だけは**認識器の種類が変わる**（オフライン → 逐次型）。実装の変更が他の2つより大きい。**その大きさも観察項目である。**
- **`sherpa_onnx` の master（未リリースの実装）を取り込まない。** 用語登録とビームサーチはリリース版では使えない。使おうとすると**プロセスが終了する**。
- 結果は `notes/voice_recognition_performance_tuning/spike/nemotron.md` に書く。**`main` にはマージしない。**

## 2. 背景

### 仮説

言語の品質区分が優先順位と一致する（日本語＝最上位・英語＝最上位・**普通話＝二番手**）。句読点と大文字にも対応する。

### 確認済みの制約（`research/opus_repropose_v3.md` §1-B-1、§1-B-2）

- **リリース版（1.13.3 も 1.13.8 も）では、ビームサーチも用語登録も使えない。** 該当実装は `greedy_search` 以外を受け取ると異常終了する。実装は master にのみある
- **展開後は約650MB で、現行の625MB より大きい**（453MB は圧縮値）
- 発話ごとの**言語指定は現行版でも動く経路がある**（`OnlineStream.setOption` で `language` を渡す）

### 答える問い

- 日本語は現行と比べてどうか（**逐次型なので、発話全体を見てから決める現行より落ちる可能性がある**）
- 日英混在はどう出るか。**発話ごとの言語判定と、1文の中の混在は別の話**である
- 普通話は実用になるか（二番手の区分なので、期待を上げない）
- オフラインから逐次型へ移す実装は、どのくらいの大きさか

## 5. エージェントが行う手順

1. **最初に飛ばす条件を判定する。** `spike/sensevoice.md` と `spike/qwen3.md` を読み、両方で日本語が明確に落ちていれば、**ここで終わる**（記録に理由を書く）。
2. ブランチを切り、`sherpa_onnx` を 1.13.8 にする。
3. S3・S4 の記録と音声があることを確認する。
4. S3 で作った「固定 wav を流す dev 経路」を用意する。
5. **モデルの取得手順を用意する**（実行は人）。対象は `sherpa-onnx-nemotron-3.5-asr-streaming-0.6b-1120ms-int8-2026-06-11`。
   - **1120ms 版を使う。** チャンクが大きいほど精度が高いと公式が書いており、この spike では精度を見たいため
   - 中身は `encoder.int8.onnx` / `decoder.int8.onnx` / `joiner.int8.onnx` と `tokens.txt` の**3ファイル構成**
   - 置き場所は S6・S7 と同じ流儀（`getApplicationSupportDirectory()` 配下の spike 用サブフォルダ）
   - **`SttModelProvisioner` 本体は変更しない**
6. **認識器を逐次型へ置き換える。** これは他の2つと違い、**クラスの種類が変わる**。
   - 現行の `lib/stt/stt_audio_worker.dart` は `OfflineRecognizer` / `OfflineRecognizerConfig` / `OfflineModelConfig` を使い、発話ごとに `createStream()` している
   - Nemotron では `OnlineRecognizer` / `OnlineRecognizerConfig` / `OnlineModelConfig` / `OnlineTransducerModelConfig`（`encoder` / `decoder` / `joiner`）を使う
   - **`decodingMethod` は `greedy_search` のままにする。** 他の値を入れるとプロセスが終了する
   - 言語の指定は `OnlineStream` の `setOption` に `language` を渡す。値の書き方（`ja` か `ja-JP` か）は**着手時に確認する。想像で書かない**
   - 入力の与え方、確定のタイミング、ストリームの使い回し方は、**着手時に `~/.pub-cache/hosted/pub.dev/sherpa_onnx-1.13.8/lib/src/online_recognizer.dart` と `online_stream.dart` を開いて確認する**
   - **この spike では、本番のパイプラインを逐次型に作り替えない。** 固定 wav を流す dev 経路の中だけで動かせばよい
7. **人に §6 を依頼する。ここで止まる。**
8. モデルが置かれたら、S3 と同じ音声を流し、区分ごとに出力をファイルへ書き出す。**言語指定あり（`ja`）と自動の両方**を試す。
9. 現行の出力と1件ずつ突き合わせる。
10. **実装の大きさを所感として残す。** どのクラスを置き換えたか、状態の持ち方がどう変わったか、本番に入れるとしたら何が追加で要りそうか。**採用判断の材料になる。**
