# S9 `hotwords` — 用語登録が効くかを見る

## 1. このセッションへの指示

- このセッションでやるのは **S9 だけ**。
- **まず実施条件を確認する。** S7 `qwen3` が RAM・熱・詰まりで落ちていたら、**この spike は実施しない。** 理由を記録に書いて終わる。
- 変えるのは**用語を渡すかどうかだけ**。モデルも設定も S7 のままにする。
- **「効いた」だけを書かない。** 無関係な語が増える方向に働いていないかを、必ず対照で見る。
- 用語を登録する画面は作らない。
- **人の手数を増やす作りにしない**（`master.md` §1 の原則）。とくに次をさせない。
  - **「今どう間違われるか」を人に書き出させない。** `answers.tsv` の `answer`（正解）と `recognized`（認識結果）の差分から、**間違われている語は機械が一覧にできる**。人はそこから登録したいものを選ぶだけにする
  - **対照音声を人に選ばせない。** 「用語を含まない音声」は、`answers.tsv` の `answer` 列を用語リストで検索すれば機械的に選べる
- 結果は `notes/voice_recognition_performance_tuning/spike/hotwords.md` に書く。**`main` にはマージしない。**

## 2. 背景

### 仮説

固有名詞・専門用語を事前に渡すと、その語の誤りが減る。

### 前提（`research/opus_repropose_v3.md` §2-3）

`sherpa_onnx` の現行版で用語登録が動く経路を持つのは **Qwen3-ASR だけ**である。Qwen3 では用語がプロンプトに注入される仕組みで、他のモデルで使う一般的な仕組みとは別物である。現行モデル（CTC）にも SenseVoice にも経路が無い。

### 答える問い

- 渡した語は、実際に正しく出るようになるか
- **用語を含まない音声で、無関係な語が挿入されるようになっていないか**
- 処理時間は増えるか

## 3. 開始条件と依存

- ブランチ: **S7 `qwen3` のブランチから枝を切る**（同じモデル・同じ設定を土台にするため）。名前は `spike/voice_recognition_performance_tuning/hotwords`
- **計画書は `main` の最新版を読む。** 枝元のコピーは古い可能性がある。枝を切った直後に `git checkout main -- notes/voice_recognition_performance_tuning/plan` で取り直す（`master.md` §1）
- **記録は spike が終わったら `main` に写す。** ファイルを1つずつ指定して写し、ブランチごとマージしない（`master.md` §1）
- **依存**: `spike/qwen3.md` があり、**条件外で落ちていないこと**
  - 落ちていたら、このセッションは**実施しない**
  - 記録が無ければ止める
- S3 の音声と `answers.tsv` を使う（正本は端末内。`.dev_models/spike_audio/` はバックアップ）
- 前提: **Android 実機**（`master.md` §1）

## 4. 作業の分担

| 誰が | 何を |
|---|---|
| エージェント | 実施条件の判定、枝の作成、**間違われている語の候補の一覧化**、用語の受け渡し、対照を含む実行、突き合わせ、記録の下書き |
| **人** | **登録する用語を選ぶ**（候補の一覧から。足したいものがあれば足す）、実機への再インストールの承認、差分が出た行の読み比べ |
| 止まる条件 | 用語を選んでもらうところ。**何を登録すべきかはエージェントが決めない** |

## 5. エージェントが行う手順

1. **最初に実施条件を判定する。** `spike/qwen3.md` を読み、条件外で落ちていれば**ここで終わる**。
2. S7 のブランチから枝を切る。
3. **間違われている語の候補を機械で一覧にする。** `answers.tsv` の `answer`（人が直した正解）と `recognized`（認識結果）が食い違う行を抜き出し、**どの語が何に化けたかを並べる**。これを人に見せて選んでもらう。
   - **白紙から書き出させない。** S3 で正解テキストを直したときの情報がすでに残っている
   - S3 の残タスクのとおり、**英語・普通話の正解は未確定**。その行は候補から外すか、未確定と分かる形で示す
5. **人に §6 を依頼して用語を選んでもらう。ここで止まる。**
6. 用語を `OfflineQwen3AsrModelConfig` の `hotwords` に渡す。書式（区切り文字・長さの上限）は、**着手時に `~/.pub-cache/hosted/pub.dev/sherpa_onnx-1.13.8/lib/src/offline_recognizer.dart` と sherpa の公開資料で確認する。想像で書かない。** **用語は画面から差し替えられるようにし、再インストールを繰り返させない。**
7. **3通りを同じ音声で流す。**
   - **A: 用語なし**（S7 の結果をそのまま使ってよい）
   - **B: 用語あり**
   - **C: 用語あり × 用語を含まない音声**（無関係な語が挿入されないかを見る対照）。**対照音声は `answers.tsv` の `answer` 列を用語で検索して機械的に選ぶ**
8. 出力をファイルに書き出し、突き合わせる。**差分が出た行だけを人に見せる。**
9. **処理時間の差も記録する。** 追加の計算を「ほぼ無料」と決めつけない。
10. 用語の数を変えて試せるなら、少数と多数の両方を見る（多いほど効くとは限らない）。

## 6. 人が行う手順

1. **間違われている語の一覧を渡されるので、登録したいものを選ぶ**（10〜30語程度）。足したいものがあれば足す

| 返してほしいもの | 形 |
|---|---|
| 選んだ用語 | 一覧に印を付けるだけでよい |
| 足したい用語 | 一覧に出ていないもので、よく話す人名・社名・製品名・専門用語があれば |

**「その語が今どう間違われるか」を書く必要はない。** `answers.tsv` の差分から機械が出す。

2. 実機への再インストールの承認と操作
3. **差分が出た行だけ**を渡されるので、それを読んで次を返す

| 返してほしいもの | 形 |
|---|---|
| 渡した語は正しく出たか | 語ごとに |
| **言っていない語が出てきたか** | 出た場合、その語と前後の文 |
| 文全体の自然さ | 用語は合っているが文が不自然になっていないか |

## 8. やらないこと

- 用語を登録する**本番の**画面の実装（dev 画面から差し替えるのはよい）
- モデル・区切り設定・ライブラリの変更
- 他のモデルで用語登録を試すこと（現行版では経路が無い）
- 副作用の確認を省くこと
- **間違われている語を人に書き出させること**（`answers.tsv` の差分から出す）
