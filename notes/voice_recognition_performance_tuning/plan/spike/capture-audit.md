# S2 `capture-audit` — 収音と発話境界を診断する

## 1. このセッションへの指示

- このセッションでやるのは **S2 だけ**。他の spike には進まない。
- **アプリの本番挙動を変えない。** これは測定だけの spike である（録り込み先を渡す debug 限定の一手は S3 で入っている。その延長に留める）。
- しきい値を**直さない**。直すのは S5 `segmentation`。ここでは「どこが欠けているか」を見つけるだけ。
- **S3 の足場から枝を切る。** 音声を保存する仕組みを作り直さない。足すのは**生 PCM 側だけ**である。
- 音声の保存には、既にある `sherpa_onnx` の `writeWave` を使う。**wav を書く仕組みを自作しない。**
- **人の手数を増やす作りにしない**（`master.md` §1 の原則）。とくに次をさせない。
  - 長い音源の中から、切り出しに対応する箇所を**人に探させない**。機械が対応区間を切り出して並べる
  - どの条件で喋ったかを**人に書き写させない**。画面で押せるようにする
  - 聴感メモを**チャットで返させない**。行が用意されたファイルに、気づいたものだけ書いてもらう
- 途中で人が耳で聴く必要がある。**そこで止まり、人に頼み、返ってきた聴感メモで続きを書く。**
- 結果は `notes/voice_recognition_performance_tuning/spike/capture-audit.md` に書く。**`main` にはマージしない。**

## 2. 背景

### 仮説

語頭・語尾の欠けなど、**モデルを替えても直らない取りこぼし**が、収音か発話の区切りの側にある。

### 答える問い

- 切り出し前には聞こえる語が、切り出し後に消えていないか
- 停止時に投入されない端数（最大512サンプル ≒ 32ms）は、実際に語尾を削っているか
- 短い相づち、30秒の上限、小声、遠距離、雑音、入力機器の切り替えで何が起きるか

### S3 から分かっていること（この spike の出発点）

- **`_kMaxSpeechDuration`（30.0 秒）が上限として効いていない。** 33.56 秒・35.48 秒・37.17 秒の区切りが実際に出た。**まずここを確かめる**
- **一度区切った wav を VAD に流し直すと、さらに細かく割れる**（24件 → 31区切り）。切り出した音の端に無音が残るためと考えられる
- 空の認識結果が2件あり、うち1件は **6.11 秒**。VAD が6秒間を発話と判断したのに認識器が1文字も返していない。**その6秒に何が入っていたかを、この spike で耳で確かめられる**

### 関係する現行コード

- `lib/stt/stt_audio_worker.dart`
  - `_AudioEngine.acceptAudio`… 受け取った PCM を Float32 に変換し、512サンプル窓で VAD に渡す
  - `_AudioEngine.stopListening`… VAD を flush するが、**変換バッファ `_floatBuffer` の残り（512未満）は投入していない**
  - `_AudioEngine._captureSegment`… S3 で入れた、切り出し後の wav を保存する経路。**ここに生 PCM 側を足す**
  - VAD の設定定数（`_kMinSilenceDuration` = 1.5 / `_kMinSpeechDuration` = 0.25 / `_kMaxSpeechDuration` = 30.0）
- `lib/pages/dev/catalog/sections/stt/stt_capture_section.dart`… S3 で作ったラベル付け画面。**条件の列をここに足す**

## 4. 作業の分担

| 誰が | 何を |
|---|---|
| エージェント | 枝の作成、生 PCM の保存と対応区間の切り出し、条件チップの追加、端数のログ、聴き比べ用のペアの書き出し、突き合わせ、記録の下書き |
| **人** | 決められた条件で喋る、**ペアを聴き比べて「消えた語」を判断する**、気づいたものだけ用意された行に書く |
| 止まる条件 | 聴き比べ用のペアが手元に揃ったところ。ここでエージェントは待ち、人の聴感メモで続きを書く |

## 5. エージェントが行う手順

1. S3 のブランチから枝を切る。**S3 の記録と足場があることを確認する。無ければ止める。**
2. **生 PCM を保存する経路を足す。** 切り出し後の wav は S3 の録り込みがすでに保存しているので、足すのは生側だけ。
   - マイクから届いた PCM を、そのまま1本の wav にためて保存する（`writeWave` を使う）
   - **生 PCM の先頭からのサンプル位置を数え続ける。** VAD が発話を返したとき、その発話が生のどの区間に当たるかを記録する
3. **聴き比べのペアを機械が作る。** これがこの spike の要である。
   - 切り出し後の wav 1件ごとに、**生 PCM から同じ区間（＋前後 0.5 秒ほどの余白）を切り出した wav** を作る
   - ファイル名を対にする（例: `0007_raw.wav` / `0007_vad.wav`）。**人が長い音源の中を探さなくても、短い2本を並べて聴けば済む状態にする**
   - 余白を付けるのは、**切り出しの外に語が落ちていないか**を聴くため。余白なしでは「欠けていない」ようにしか聞こえない
4. **条件を押せるようにする。** `stt_capture_section.dart` に条件のチップ列を足す（`ふつう` / `相づち` / `小声` / `遠距離` / `生活音` / `30秒超` / `停止直後` / `機器切替`）。**既定は `ふつう`** とし、人はそれ以外のときだけ押す。値は `answers.tsv` と同じ流儀で端末内に残す。
5. `stopListening` の端数を確かめる材料を作る。**コードは直さない。** 停止時に `_floatBuffer` に何サンプル残っていたかを**ログに出すだけ**にする。
6. **`maxSpeechDuration` を確かめる。** S3 で 37.17 秒の区切りが出ている。切り出しの長さを一覧にし、30 秒を超えたものを数える。**ここでは直さない**（S5 の担当）。
7. 実機に入れて人に §6 を依頼する。**ここで止まる。**
8. 人が喋り終えたら、`scripts/pull_android_spike_audio.sh` の流儀で**ペアと聴感メモの雛形を手元へ吸い出す**。
   - 雛形は1ペア1行の TSV。**条件・切り出し長・認識結果はすでに埋まっている状態**にし、人が書くのは気づいたことだけにする
9. 人の聴感メモが返ったら、次を突き合わせる。
   - 生に聞こえて切り出し後に無い語があるか
   - 切り出し後の先頭・末尾が不自然に切れていないか
   - 停止時の残りサンプル数のログと、語尾の欠けが対応しているか
   - **空の認識結果になった区間に、実際は何が入っていたか**（S3 の 6.11 秒の空）
10. 見つかった事例を §7 の表に整理する。**件数と条件を書き、原因を1つに決めつけない。**

> **聴き比べを端末の中でやらせない。** 端末に再生画面を作るには音声再生の依存を増やすことになり、この spike の目的に対して大きすぎる。1コマンドで手元へ吸い出し、**ペアになった短い wav を母艦で聴く**のがいちばん手数が少ない。ここは「受け渡しを作らない」原則の例外として、意図してそうする。

## 6. 人が行う手順

**いつも通り momeo で喋るだけ**。録音の開始操作も、ファイルの取り出しも要らない。
ただし S3 と違い、**条件を変えて喋ってほしい**。

1. 次をひととおり話す。話し終えたら、dev カタログ「STT → 録り込み」で**`ふつう` 以外のものだけ条件を押す**
   - ふつうの独り言（数文）
   - 短い相づち（「うん」「はい」など）
   - 小声
   - 端末から離れて（1〜2m）
   - 生活音のある場所で
   - 30秒を超えて話し続ける
   - 話し終えた直後に録音を止める（語尾が残るかを見るため）
   - 途中でイヤホンや Bluetooth に切り替える
2. エージェントが手元に**ペアの wav と、行が埋まった聴感メモ**を用意する。ペアを聴き比べて、**おかしいものだけ**次を書き足す

| 書いてほしいもの | 形 |
|---|---|
| 消えた語 | 「生では『〜』と言っているが切り出し後に無い」のように、**実際の語**で |
| 切れ方 | 頭が切れる / 尻が切れる / 丸ごと無い |
| 気づいたこと | 何でも。空欄のままでよい行があってよい |

**問題が無かったペアは触らない。** 空欄のままが「問題なし」の意味になる。

## 8. やらないこと

- しきい値・前後余白の変更（S5 の担当）
- 端数を投入するコード修正（診断が先。直すかどうかは S5 以降で決める）
- `maxSpeechDuration` が効いていない原因の修正（S5 の担当。ここでは事実の確認だけ）
- モデルの差し替え、ライブラリの更新
- 本番の録音・保存・画面への変更
- 自動採点や波形の可視化ツールの作成
- **音声再生の画面や依存の追加**（手元で聴けば済む）

## 9. 完了条件と、次へ渡すもの

**完了条件**: 「モデルを替えても直らない取りこぼしがあるか」について、**事例か、事例が見つからなかったという事実**が記録に残っていること。加えて、**30 秒を超える切り出しが実際に出るか**が確認されていること。

**次へ渡すもの**: `spike/capture-audit.md` のみ。**コードはマージしない。** 生 PCM の保存と対応区間の切り出しは、S5 でも使えるのでブランチに残す。

- 境界の問題が見つかった → S5 `segmentation` を実施する
- 見つからなかった → S5 は後回しにしてよい。ただし **`maxSpeechDuration` が効いていない件は S5 で扱う**（S3 で確認済みのため、S2 の結果とは独立している）
