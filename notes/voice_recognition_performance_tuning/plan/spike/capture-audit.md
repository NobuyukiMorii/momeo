# S2 `capture-audit` — 収音と発話境界を診断する

## 1. このセッションへの指示

- このセッションでやるのは **S2 だけ**。他の spike には進まない。
- **アプリの本番挙動を変えない。** これは測定だけの spike である。
- しきい値を**直さない**。直すのは S5 `segmentation`。ここでは「どこが欠けているか」を見つけるだけ。
- 音声の保存には、既にある `sherpa_onnx` の `writeWave` を使う。**wav を書く仕組みを自作しない。**
- 途中で人が耳で聴く必要がある。**そこで止まり、人に頼み、返ってきた聴感メモで続きを書く。**
- 結果は `notes/voice_recognition_performance_tuning/spike/capture-audit.md` に書く。**`main` にはマージしない。**

## 2. 背景

### 仮説

語頭・語尾の欠けなど、**モデルを替えても直らない取りこぼし**が、収音か発話の区切りの側にある。

### 答える問い

- 切り出し前には聞こえる語が、切り出し後に消えていないか
- 停止時に投入されない端数（最大512サンプル ≒ 32ms）は、実際に語尾を削っているか
- 短い相づち、30秒の上限、小声、遠距離、雑音、入力機器の切り替えで何が起きるか

### 関係する現行コード

- `lib/stt/stt_audio_worker.dart`
  - `_AudioEngine.acceptAudio`… 受け取った PCM を Float32 に変換し、512サンプル窓で VAD に渡す
  - `_AudioEngine.stopListening`… VAD を flush するが、**変換バッファ `_floatBuffer` の残り（512未満）は投入していない**
  - VAD の設定定数（`_kMinSilenceDuration` = 1.5 / `_kMinSpeechDuration` = 0.25 / `_kMaxSpeechDuration` = 30.0）
- `lib/pages/dev/catalog/sections/stt/stt_vad_section.dart`… マイクから VAD へ流して区切りを見る既存画面

## 3. 開始条件と依存

- ブランチ: `main` から `spike/voice_recognition_performance_tuning/capture-audit` を切る
- 依存する spike: **なし**（S1 と並行でもよい）
- 前提: 実機で録音でき、端末から wav を取り出せること

## 4. 作業の分担

| 誰が | 何を |
|---|---|
| エージェント | ブランチ作成、音声を保存する dev 限定の変更、実機で流す準備、取り出した wav の突き合わせ、記録の下書き |
| **人** | 実機の操作、決められた文言の発話（小声・遠距離・相づち等を含む）、**保存された wav を耳で聴いて比べること**、端末からの wav の取り出し |
| 止まる条件 | wav が保存できたところ。ここでエージェントは待ち、人の聴感メモで続きを書く |

## 5. エージェントが行う手順

1. ブランチを切る。
2. `lib/pages/dev/catalog/sections/stt/stt_vad_section.dart` に、**dev 限定で2種類の音声を保存する**最小の変更を入れる。
   - **A: 生の入力**… マイクから届いた PCM を、そのまま1本の wav にためて保存する
   - **B: 切り出し後**… VAD が返した発話チャンクを、1発話ずつ別の wav に保存する
   - 保存には `sherpa_onnx` の `writeWave({filename, samples, sampleRate})` を使う。サンプルは `[-1, 1]` の `Float32List`、サンプリングレートは 16000。
   - 保存先は端末の書き込み領域。`lib/stt/stt_model_provisioner.dart` が `getApplicationSupportDirectory()` を使っているので、同じ場所の下に spike 用のサブフォルダを切ればよい。
   - 対応する A と B が後から突き合わせられるよう、**ファイル名に通し番号と時刻を入れる**。
3. `stopListening` の端数を確かめる材料を作る。**コードは直さない。** 停止時に `_floatBuffer` に何サンプル残っていたかを**ログに出すだけ**にする。
4. 実機に入れ、人に §6 を依頼する。**ここで止まる。**
5. 人から wav と聴感メモが返ったら、次を突き合わせる。
   - A に聞こえて B に無い語があるか
   - B の先頭・末尾が不自然に切れていないか
   - 停止時の残りサンプル数のログと、語尾の欠けが対応しているか
6. 見つかった事例を §7 の表に整理する。**件数と条件を書き、原因を1つに決めつけない。**

## 6. 人が行う手順

1. 実機で dev カタログの `STT` → `VAD 区切り` を開き、録音を始める
2. 次をひととおり話す。**それぞれ、どれを話したかをメモに残す**
   - ふつうの独り言（数文）
   - 短い相づち（「うん」「はい」など）
   - 小声
   - 端末から離れて（1〜2m）
   - 生活音のある場所で
   - 30秒を超えて話し続ける
   - 話し終えた直後に録音を止める（語尾が残るかを見るため）
   - 途中でイヤホンや Bluetooth に切り替える
3. 端末から wav を取り出す（Android なら `adb`、iOS ならファイル共有など。取り出し方はエージェントが手順を用意する）
4. **A と B を聴き比べて**、次を返す

| 返してほしいもの | 形 |
|---|---|
| 消えた語があったか | 「A では『〜』と言っているが B に無い」のように、**実際の語**で |
| どの条件で起きたか | 小声 / 遠距離 / 相づち / 停止直後 / 機器切り替え など |
| 切れ方 | 頭が切れる / 尻が切れる / 丸ごと無い |
| 起きた回数の感触 | 「毎回」「たまに」「1回だけ」程度でよい |

## 7. 観察・記録の枠

`notes/voice_recognition_performance_tuning/spike/capture-audit.md` に写す表。

| # | 条件 | A（生）で聞こえる語 | B（切り出し後）の状態 | 切れ方 | 頻度 |
|---|---|---|---|---|---|
| 1 | | | | | |

あわせて次を文章で残す。

- 停止時に `_floatBuffer` に残っていたサンプル数（ログの実測値）と、語尾の欠けとの対応
- 30秒の上限で切れたときの前後のつながり
- **見つからなかった条件も書く**（「小声では問題が出なかった」も結果である）
- 32ms の端数を、精度問題全体の原因と**決めつけない**

## 8. やらないこと

- しきい値・前後余白の変更（S5 の担当）
- 端数を投入するコード修正（診断が先。直すかどうかは S5 以降で決める）
- モデルの差し替え、ライブラリの更新
- 本番の録音・保存・画面への変更
- 自動採点や波形の可視化ツールの作成

## 9. 完了条件と、次へ渡すもの

**完了条件**: 「モデルを替えても直らない取りこぼしがあるか」について、**事例か、事例が見つからなかったという事実**が記録に残っていること。

**次へ渡すもの**: `spike/capture-audit.md` のみ。**コードはマージしない。**

- 境界の問題が見つかった → S5 `segmentation` を実施する
- 見つからなかった → S5 は後回しにしてよい
