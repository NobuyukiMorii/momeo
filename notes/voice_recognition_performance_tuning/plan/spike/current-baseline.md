# S3 `current-baseline` — 現行モデルの素の出力を固定音声で記録する

> **実施済み。** 結果は `notes/voice_recognition_performance_tuning/spike/current-baseline.md`。
> 足場のコードはブランチ `spike/voice_recognition_performance_tuning/current-baseline`（コミット `96cf384`）にある。**やり残しは §10。**

## 1. このセッションへの指示

- このセッションでやるのは **S3 だけ**。モデルもライブラリも**替えない**。
- この spike は、**後続すべてが使い回す共通の足場**を作る。次の2つの dev 経路である。
  - **いつも通りアプリを使うだけで評価音声が溜まる**（本番のリスニングが、区切った1発話ぶんを wav として残す）
  - **その wav を読んで認識器に流し、結果をファイルに出す**
- **これ以上は作らない。** 自動採点、グラフ表示、本番の画面への作り込みはしない。
- 評価用の音声をここで揃える。以後の spike はこの音声を使う。
- 途中で人が実機で喋る必要がある。**そこで止まり、人に頼み、溜まった音声で続きを進める。**
- **人の手数を増やす作りにしない。** 別アプリでの録音・ファイルの転送・形式の変換・1発話ごとのラベル付けを人にさせない。
- 結果は `notes/voice_recognition_performance_tuning/spike/current-baseline.md` に書く。**`main` にはマージしない。**

## 2. 背景

### 仮説

- 現行モデルは**英語をまともに出せない**（`research/opus_repropose_v3.md` §1-C-1。語彙にラテン文字のマージが1つも無く、大文字トークンが0個であることから推論したが、**実際に通したことはない**）
- **空の認識結果**が一定の頻度で出ている（`lib/providers/listening_providers.dart` の `emptyResultCount`。コメントでは「咳・物音の誤検知」としている）

### 答える問い

- 英語混じりを通すと、実際に何が出るか（カタカナ化 / 欠落 / 小文字の綴り / 無音扱い）
- 空の認識結果はどのくらいの頻度で、どんな音で起きているか
- 日本語・英語・普通話それぞれで、素の出力はどうなっているか

### なぜ固定音声が要るか

現行の dev カタログのセクションは**すべてマイク入力**で、同じ音声を流し直せない。モデルを比べるには同じ音声を同じ入口から入れる必要がある。ここで1回だけ作る。

音声は**このアプリ自身で録る**。別のアプリで録ると、そのアプリ独自の圧縮やノイズ抑制がかかり、momeo が `record` 越しに受け取る音と別物になる。実機の実マイクを通った音でなければ、足場として正しくない。

## 3. 開始条件と依存

- ブランチ: `main` から `spike/voice_recognition_performance_tuning/current-baseline` を切る
- 依存する spike: **なし**
- 前提: **Android 実機**にモデルが置いてあること（`scripts/place_android_device_models.sh`）
- **この spike は Android で行う。** iOS はバンドルリソース同梱しか配置の経路が無く、「新しい配布経路は作らない」に触れる

## 4. 作業の分担

| 誰が | 何を |
|---|---|
| エージェント | ブランチ作成、評価音声を録り込む dev 経路の作成、固定 wav を流す dev 経路の作成、実行と結果の書き出し、記録の下書き |
| **人** | 実機で喋って評価音声を溜める、認識が違うものだけ正解テキストを直す、実機の操作 |
| 止まる条件 | 2つの dev 経路ができたところ。ここでエージェントは待ち、人が溜めた音声で続きを進める |

## 5. エージェントが行う手順

1. ブランチを切る。
2. **評価音声が、いつも通りアプリを使うだけで溜まるようにする。**
   - 録音用の画面を別に作らない。本番のリスニング画面は `PageView` の中で動き続けるため、別画面で録ろうとすると**マイクの取り合い・認識器の二重読み込み・本番メモの汚染**が起きる。
   - 本番のリスニングが使う `SttListeningPipeline` に録り込み先を渡す。渡すのは **debug ビルドのときだけ**とし、release では何も残らないようにする。
   - 保存は音声 isolate の中で行う。VAD が区切った `SpeechSegment.samples` を `sherpa_onnx` の `writeWave()` で書き出す。**wav を組み立てるコードを自作しない。**
   - 音声だけでなく、**認識結果も対にして1行ずつ追記する**（`captured.tsv`）。音と認識結果は対で意味を持つ。
   - 区分と正解テキストを付ける画面を、dev カタログに1つ作る。**録音操作は持たせない。**
     - 既定は「日本語・調整用・認識結果のまま」にし、**そこから外れるものだけ人が触る**状態にする
     - 認識結果と正解テキストの両方を残すことで、どれが認識ミスだったかが2列の差分で分かる
3. **固定 wav を流す dev 経路を1つ作る。** `catalog_page.dart` の `_Section(title: 'STT', ...)` に項目を足す。
   - wav の読み込みは `sherpa_onnx` の `readWave(path)` を使う。戻り値 `WaveData` は `samples`（`[-1,1]` の `Float32List`）と `sampleRate` を持つ。**wav を解析するコードを自作しない。**
   - 認識器は現行と同じものを使う。`lib/stt/stt_audio_worker.dart` の `SttAudioWorker.spawn({modelPath, tokensPath})` を使う。モデルのパスは `lib/stt/stt_model_provisioner.dart` の `SttModelProvisioner().provision()` から取る（`nemoModel.path` / `nemoTokens.path`）。
   - **VAD を通すかどうかは、両方できるようにする。** 「wav を丸ごと1発話として認識器へ渡す」経路と、「wav を VAD に流して区切ってから認識する」経路の2つ。前者はモデル比較用、後者は本番に近い挙動の確認用。
   - 読む先は、録り込みが溜める場所と同じにする。**音声の受け渡しを人にさせない。**
   - 出力は**画面だけにしない**。1件ごとに次をテキストファイルへ書き出す: 入力ファイル名 / 認識テキスト / 音声長 / 処理時間。空文字の場合も**空だったと分かる形で**書く。
4. **手元への吸い出しはバックアップ用に留める。** 録り込みも実行も端末内で完結するため、ふだんは転送が要らない。アプリを入れ直すと端末内の音声が消えるので、そのための回収と復元だけを用意する。`.dev_models/` は `.gitignore` で丸ごと無視されているので、**その下に `spike_audio/` と `spike_results/` を作って使う**（`.gitignore` を変更しなくて済む）。置き方は `scripts/place_android_device_models.sh` の流儀に合わせる。**新しい配布経路は作らない。**
5. **ここで止まる。** 人に §6 を依頼する。
6. 音声が揃ったら、全件を2つの経路（丸ごと / VAD 経由）で流し、出力ファイルを回収する。
7. 結果を §7 の枠に整理する。**英語混じりの出力は、加工せず原文のまま残す。**

## 6. 人が行う手順

**いつも通り momeo を使って喋るだけ**。別のアプリで録らない。転送も変換もしない。録音の開始操作も要らない。
debug ビルドで喋ると、区切られた発話が自動で溜まる。

溜まったあと、dev カタログ「STT → 録り込み」で次をする。

1. 一覧を見て、**認識が違うものだけ正解欄を直す**（合っているものは触らない）
2. 日本語・調整用**以外**のものだけ、区分と用途を押して変える

### 録ってほしい音声

**実際にメモを取るときと同じ距離・同じ環境で**喋る。合成音声だけにしない。

| 区分 | 目安 | 入れてほしいもの |
|---|---|---|
| 日本語のみ | 多め | 日常の独り言、言い直し、否定、数字、日時、人名、専門用語 |
| 日本語＋英語 | 中くらい | 英語として発音する単語、カタカナで言う外来語、略語、製品名やサービス名 |
| 英語のみ | 少し | 短い文 |
| 普通話 | 少し | 短い文（話せる人がいなければ「未収録」と書いて飛ばしてよい） |
| 雑音・他者・テレビ | 少し | 自分が話していない音。空の認識結果を見るため |

**「うまく認識できなかった実際の例」を必ず入れる。** これが今回いちばん重要な材料になる。実機の実マイクで録るため、直そうとしなくても自然に溜まる。

### 調整用と最終判定用

後の spike で設定を振るときは調整用だけを見て、最後に最終判定用で確かめる。どちらも同じ要領で録る。

## 10. 実施したあとに残っていること

この spike は実施済みだが、次の3つが残っている。**後続が前提にできないので、必要になった spike で拾う。**

| 残り | 影響 |
|---|---|
| **`最終判定用` の音声が未収録**（録り込みはすべて `調整用`） | S5 が「最後に最終判定用で確かめる」を実行できない。設定を振る前に短く録り足す必要がある |
| **英語・普通話の正解テキストが未確定** | 記録 §7 では英語2件・普通話2件、§1・§3 では6件と件数の記述が揺れている。**着手時に `answers.tsv` で実数を確かめる。** 認識が壊れていて出力から復元できないため、人が聴いて書き起こすしかない |
| **録り込みの総数の記述が揺れている**（記録 §6 は24件、§6.1・§7 は25件） | 割合を書き直すときは `captured.tsv` の行数を数え直す |
| **`noise` 区分11件は他者音声（動画）** | マイクからの距離も話し方も普段のメモと違うため、精度のベースラインには使わない。英語表記の事例としてのみ使う |

**この spike で分かった、後続の前提を変える事実は記録の §5〜§6.2 にある。** とくに次の3つは、それぞれの spike の計画に織り込み済みである。

- 「現行モデルは英語を出せない」という仮説は**外れ**。実態は「**表記が定まらない**」（課題②の立て直し）
- 固定 wav の足場は**決定的**（同じ wav で 25/25 一致）だが、**録音時の結果と流し直しの結果は食い違う**（wav 保存時の int16 丸め）。比較は必ず**流し直し同士**で行う
- `_kMaxSpeechDuration` が上限として効いていない（30.0 秒設定で 37.17 秒の区切りが出る）
