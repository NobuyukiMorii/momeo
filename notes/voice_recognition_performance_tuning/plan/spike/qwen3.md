# S7 `qwen3` — Qwen3-ASR 0.6B に差し替えて比べる

## 1. このセッションへの指示

- このセッションでやるのは **S7 だけ**。用語登録の評価はしない（それは S9 `hotwords`）。
- 変えるのは**認識モデルだけ**。ライブラリは 1.13.8 のまま、区切り設定は S5 で決まった値のままにする。
- **配布の作り込みをしない。** モデルを端末に手で置いて、固定パスで読むだけでよい。
- この候補は**常駐RAM・発熱・待ち行列の詰まりで落ちる可能性が高い**。**精度より先に、そこを見て早く打ち切る。**
- **既定の出力長上限（`maxNewTokens` = 128 / `maxTotalLen` = 512）を必ず確認する。** 長い発話が途中で切れたとき、それをモデルの認識能力の不足と取り違えない。
- 結果は `notes/voice_recognition_performance_tuning/spike/qwen3.md` に書く。**`main` にはマージしない。**

## 2. 背景

### 仮説

多言語を1モデルで扱え（課題②③）、**sherpa_onnx の現行版で用語登録が動く唯一の候補**なので、課題①に対する能動的な手段を持つ（`research/opus_repropose_v3.md` §2-3）。ただし**RAM・発熱・詰まり**で落ちうる。

### 答える問い

- 日本語・日英混在・英語・普通話はどうか
- **常駐RAM はどこまで増えるか。バックグラウンド録音中に OS に落とされないか**
- 発話率を上げたとき、未処理が増え続けないか
- 出力が途中で切れる事例はあるか

### 注意（`research/opus_repropose_v3.md` §1-E）

「重み読み出しが現行の約23倍」という見積もりはあるが、**絶対値に直すと1日あたり電池の1%台**で、それ単独では不採用の理由にならない。**電池の倍率を理由にここで打ち切らないこと。** 見るべきは RAM と熱と詰まりである。

  - `spike/current-baseline.md` と `.dev_models/spike_audio/` の音声

## 5. エージェントが行う手順

1. ブランチを切り、`sherpa_onnx` を 1.13.8 にする。
2. S3・S4 の記録と音声があることを確認する。**無ければ止める。**
3. S3 で作った「固定 wav を流す dev 経路」を用意する。
4. **モデルの取得手順を用意する**（実行は人）。対象は `sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25`。
   - **複数ファイル構成**である。frontend・encoder・decoder の3つの onnx と、tokenizer のディレクトリ。現行モデル（単一ファイル）とは形が違う
   - 展開後の合計は約1GB。**端末の空き容量を先に確認してもらう**
   - 置き場所は S6 と同じ流儀（`getApplicationSupportDirectory()` 配下の spike 用サブフォルダ。Android は `/data/local/tmp` 経由 → `run-as jp.momeo` コピー）
   - **`SttModelProvisioner` 本体は変更しない**
5. **認識器の設定を差し替える。** 使う設定クラスは `OfflineQwen3AsrModelConfig`。`OfflineModelConfig` の `qwen3Asr` に渡す。
   - フィールドは `convFrontend` / `encoder` / `decoder` / `tokenizer` / `maxTotalLen` / `maxNewTokens` / `hotwords` ほか
   - **`maxNewTokens` の既定は 128、`maxTotalLen` の既定は 512。** 長い発話で足りるかを最初に確かめ、足りなければ上げて、**上げたことを記録する**
   - `hotwords` はこの spike では**空のまま**にする（評価は S9）
   - `OfflineModelConfig` の `tokens` に何を渡すかは、**着手時に `~/.pub-cache/hosted/pub.dev/sherpa_onnx-1.13.8/lib/src/offline_recognizer.dart` を開いて確認する**。想像で書かない
6. **人に §6 を依頼する。ここで止まる。**
7. モデルが置かれたら、**まず短い予備確認を行う。** 起動するか、RAM がどこまで増えるか、異常終了しないか、出力が途中で切れないか。**ここで明らかに条件外なら、精度の評価に進まずに打ち切る。**
8. 通過したら、S3 と同じ音声を流し、区分ごとに出力をファイルへ書き出す。
9. 現行の出力と1件ずつ突き合わせる。

## 6. 人が行う手順

1. モデルを取得する（**約1GB**。時間と通信量がかかる）
2. 端末の空き容量を確認し、モデルを置く
3. 実機への再インストールの承認と操作
4. **長時間の連続動作を試す。** 充電ケーブルを外し、録音を続けたまま放置して、次を見る
   - 端末が熱くなるか
   - アプリが落ちていないか
   - 話してから文字が出るまでの待ちが、時間とともに伸びていないか
5. 出力を読み、次を返す

| 返してほしいもの | 形 |
|---|---|
| 日本語の読み返しやすさ | 現行と比べて。**実際の出力を引用して** |
| 英語混じりの見え方 | 英字で出たか、カタカナか、消えたか |
| 長時間動かしたときの様子 | 発熱・落ちた・待ちが伸びた、など |
| 途中で切れた出力 | あれば、その文 |
