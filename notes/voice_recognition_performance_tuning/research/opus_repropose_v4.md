# 音声認識の課題に対する再提案 v4

## この文書について

- **目的**: `opus_repropose_v3.md`（机上の提案）を、**実機で測り終えた結果で組み直す**こと。v3 を守ることが目的ではない。
- **v3 との一番の違い**: v3 は「何を確かめるか」を書いた文書だった。**v4 は「確かめ終わったので何を採り、何を採らず、何を解けないと認めるか」を書く文書**である。
- **日付**: 2026-09-21
- **材料**: `plan/master.md` が分解した spike のうち、**実施したもの全部**（S1・S2・S3・S4・S5・S6・S7・S8・S10・`lead-padding`）。記録は `spike/` にある。
- **根拠の種別**: 本文では次を区別する。
  - **【実測】** 実機で測った。記録と生データが `spike/` と `.dev_models/` にある
  - **【本人】** 本人が耳で聴いた、または読み比べて判断した
  - **【推論】** 測った事実から導いた判断。測ってはいない
  - **【未測定】** 測っていない
- **前提条件**（v3 から変わらない）: クラウドを使わない。製品で使う認識モデルは1つ。表示したテキストは書き換えない。電池と発熱は採用条件。即時性は譲ってよいが「遅くてよい」は「重くてよい」ではない。優先順位は ①日本語精度 → ②日本語中の英語 → ③英語・普通話 → ④自分と他人の識別。
- **本書は方向性の提案**であり、実装計画ではない。**本書を書くにあたって新しい測定は行っていない。**

## 2. 現行モデルの実像

v3 の時点では推論だった部分が、実測で像を結んだ。

### 2-1. 日本語は実用の水準にある【実測】

人名（徳川家康・織田信長）、数字（1600・1860）、専門語（文明開化）が通る。台本コーパスの逐語採点で、最終判定用の日本語文は 89.9〜97.3%。

### 2-2. ただし3つの壊れ方がある


| #   | 壊れ方      | 実例                        | 気付けるか            |
| --- | -------- | ------------------------- | ---------------- |
| 1   | **空の結果** | 25件中1〜2件                  | 空と分かる            |
| 2   | **崩壊**   | 34.65秒の英語 → `そうシ`（3文字）    | **気付ける**（明らかに短い） |
| 3   | **節の脱落** | 「世界史についてはよく知っています」が丸ごと消える | **気付けない**        |


**3 が一番たちが悪い。** 日本語の地の文として自然に読めてしまうため、読み返しても落ちたことが分からない。

**3 は系統の違う2モデル（SenseVoice・Qwen3）が独立に復元し、本人が「言っている」と確認した**【実測・本人】。**空文字・崩壊に並ぶ3つ目の壊れ方として確定している。**

### 2-3. 課題②の実態は「表記が定まらない」【実測】

「英語が出ない」ではない。`I think` が同一セッション内で8通りに散り、**同じ音を流し直すだけでも変わる**（`iphene` / `iphone`）。
原因は**モデルの判断が境界上にある**ことで、wav 保存時の int16 丸め（振幅 1/32768 程度）だけで 25件中16件の出力が変わる。

**したがって後処理の置換辞書では直らない。** 置換のキーが安定しないためで、S10 が実データで確認した。

### 2-4. 取りこぼしは語頭だけ【実測】

S2 が8条件（語頭・語尾・相づち・小声・遠距離・生活音・機器切替・30秒境界）を実測し、**問題が出たのは語頭だけ**だった。
30発話中9件で切り出しの手前に音が残り、最大 150ms の1件では語が消えていた。**モデルが読めなかったのではなく、渡っていなかった。**

**収音側（マイク・機器切替・生活音）を疑う筋は閉じてよい。**

## 3. 候補の最終比較

**すべて同じ音声・同じ経路・同じライブラリ（1.13.8）で測り、各回の先頭で現行 NeMo を流して S4 と 25/25 一致することを確認している**【実測】。差はモデルに帰属する。


|                 | 現行 NeMo CTC    | **SenseVoice Small** | Qwen3-ASR 0.6B | Nemotron 3.5         |
| --------------- | -------------- | -------------------- | -------------- | -------------------- |
| 展開後サイズ          | 625MB          | **約230MB**           | 約937MB         | 682MB                |
| 最大PSS           | 1,262〜1,393MB  | **778MB**            | **4,010MB**    | 1,014MB              |
| 426秒の処理時間       | 46秒            | **31〜42秒**           | **258〜1,655秒** | 106〜120秒             |
| 空の結果（凍結25件）     | 1件             | **0件**               | 2件             | 5件                   |
| 決定性             | あり             | あり                   | あり             | あり                   |
| 日本語（長い発話）       | 基準             | **落ちない**（逐語採点は未測定）   | 落ちない           | 互角（6文で3勝3敗）          |
| **相づち（2モーラ）**   | **9/9**        | **未測定**              | 未測定            | **0/9**              |
| 節の脱落            | **落とす**        | **拾う**               | **拾う**         | 未確認                  |
| 英語のみの発話         | **崩壊**         | **全文が出る**            | **全文が出る**      | **全文が出る（大文字・句読点つき）** |

| **課題②（文中の英単語）** | 表記が定まらない       | カタカナ（**揺れない**）       | **英字で出る**      | カタカナ（**揺れる**）        |
| 判定              | —              | **唯一残る候補**           | **RAM で条件外**   | **相づちで条件外**          |




### Qwen3 — 課題②を解く唯一の手だが、積めない【実測】

`Facebook` / `iPhone` / `AirDrop` / `Mac` / `Samsung` / `IT` を英字のまま出し、`I think` の表記の種類も3候補中で最少だった。**課題②に有効な手があることは実証された。**

だが常駐RAM 4,010MB のうち Native Heap が 2,728MB を占め、**OS が捨てて逃がせない**。同時点で 970MB がスワップに出ていた。出力を切らずに出させると実時間の 3.89倍で、1発話（37秒）に148秒かかる。**次の発話は待ち行列に積まれる。**

**「解ける手はあるが、その手は積めない」** — これが課題②の現在地である。

### Nemotron — 相づちで落ちた【実測】

RAM 1,014MB は現行より小さく、速度も実時間の 25〜28%。**Qwen3 を落とした基準では落ちない。**

落としたのは中身である。`うん`・`はい`（2モーラ）を **0/9**。`なるほど`（4モーラ）は 9/9 出るので、長さの問題ではない。**前後0.5秒の無音を足しても変わらず、設定では埋められない。**

**相づちは momeo の用途の中心にある。** ここが空になる候補は、他がどれだけ良くても採れない。

加えて、逐次型は語頭の欠けに現行より弱い。**頭が欠けると無音になるのではなく別の語に化ける**（`昨日`→`脳`、`来週`→`最終`）。**読んでも間違いに気づけない。**

### *SenseVoice* — 唯一残る候補

現行の3つの壊れ方のうち、**崩壊と節の脱落を直す**。RAM は 44% 小さく、処理時間も現行以下。空は0件。出力は決定的。

代償は**日本語の文中の英単語がカタカナになる**こと。`iphone` → `アイフォン` は読めるが、`airdrop` → `エアジョロ`、`ITリテラシー` → `アティイテラス` は誤りである。数字も直らない（`1600年` → `16002年`）。

**ただし、本人が「壊滅的」と評したのは現行のカタカナ音写のほうである**【本人】。

> そもそも英語をカタカナにしている時点で、どちらも壊滅的
> そもそも中国語をカタカナにしても、意味がわかりません。良いのか悪いのか判断出来ない

**これは英語・普通話まるごとの発話について言われたもので、SenseVoice はそこを英語・漢字で出す。** 一番大きな不満に直接当たる唯一の候補である。

## 4. 提案



### 4-1. 全体の形（v3 から変えない）

```text
録音（変えない）
  ↓
Silero VAD で発話を切り出す（threshold だけ 0.35 にする）
  ↓
単一の認識器が1回だけ認識する
  ↓
確定したテキストを一度だけカードにする（書き換えない）
```

**モデルは1つ、認識は1回、表示済みテキストは書き換えない。** 実測を経ても、この形を変える理由は出なかった。

### 4-2. いま本番に入れてよいもの

**この2つは同時に入れる。** 別々に入れると、本番の土台が測った条件のどれとも一致しなくなる。


|     | 変更                           | 根拠                                    | 期待してはいけないこと                          |
| --- | ---------------------------- | ------------------------------------- | ------------------------------------ |
| 1   | `sherpa_onnx` を 1.13.8 に上げる  | 追随コストゼロ。全 spike がこの上で測られている【実測】       | **精度は上がらない。** 空も崩壊も減らない              |
| 2   | VAD に `threshold = 0.35` を渡す | 連続音で空 1件 → 0件、相づち 10件 → 11件、副作用なし【実測】 | **読みやすさは変わらない。** 本人の読み比べで差が出なかった【本人】 |


`0.25` **まで下げない。** 物音を1件余計に拾い、空が1件増える【実測】。**0.35 で止める。**

### 4-3. あわせて直すべき、記録との食い違い

**測って初めて、本番コードの記述が実装より強いと分かった。** どれも挙動は変わらないが、次に読む人を誤らせる。


| 場所                                              | 現在の記述      | 実装                                                                                          |
| ----------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------- |
| `stt_audio_worker.dart` の `_kMaxSpeechDuration` | 「上限」       | **上限ではない。** 超過時に `minSilenceDuration` を 0.1秒・`threshold` を 0.90 に切り替えて**切れやすくするだけ**【実測・コード】 |
| dev カタログの表示                                     | 「強制区切り」    | 同上。強制分割はしない                                                                                 |
| `listening_providers.dart` の `emptyResultCount` | 「咳・物音の誤検知」 | **6.11秒の空は本人の英語1文だった**【実測・本人】。この説明では付かない                                                    |




### 4-4. 課題②について、明示的に決めること

**「日本語の文中に混ざる英単語を、英字のまま正しい表記で出す」ことは、いまの条件（オンデバイス・モデル1つ・この端末）では実現できない。**

- 英字で出せたのは Qwen3 だけ【実測】
- その Qwen3 は RAM 4,010MB で積めない【実測】
- 置換辞書は構造的に届かない（キーが安定しない）【実測】
- SenseVoice・Nemotron はカタカナに倒れる【実測】

**これを「まだ調べ足りない」ではなく「現時点の結論」として書き残す。** 条件が変わったときに再検討する材料は §7 にある。

### 4-5. 課題③について

**現行の崩壊（英語・普通話がカタカナ音写になる）を直す手は、実在して、積める。** SenseVoice である。

**課題③は優先順位で3番目**だが、**本人が一番強い言葉で不満を述べたのはここだった**【本人】。優先順位の順番と、実際に効く順番が一致していない。

### 4-6. 課題④（自分の声の識別）

**着手しない。** ①〜③の結論が出るまで切らないという方針どおりで、①②③がこの状態である以上、順番が回ってこない。

### 4-7. 電池と発熱について、実測から言えること


|        | 実測                                                                 | どう使うか                                   |
| ------ | ------------------------------------------------------------------ | --------------------------------------- |
| 発話中の発熱 | ASR が主。CPU 9.48% → 22.19%（2.3倍）。余熱があっても発話が無ければ温度は下降、冷えていても発話があれば上昇 | **重い候補は発話が続く場面で不利。** Qwen3 を落とした判断と同じ向き |
| 1日の平均  | 常時稼働側が主。平均CPU = 9.48 + 12.71r（ポイント）で、逆転は発話率 **r=75%**              | **モデルを軽くしても1日の電池はあまり改善しない**             |
| 電池の絶対値 | **測れていない。** 段Bは全条件が画面ONで、idle と ASR が 8.9%/時 と 9.0%/時 でほぼ同じになった    | **本番の電池持ちには転用しない**                      |


**したがって「1日の電池を良くしたい」なら、モデル差し替えではなく常時稼働側の 9.48% を削る改善である**【推論】。S1 が候補として記録しているのは、record 画面の毎チャンクのメーター更新、VAD のメイン isolate 処理、本番側の常時録音変換・描画。**どちらを狙うかを先に決める。**

**SenseVoice に替えても電池が悪化する筋は考えにくい**【推論】 — RAM は 44% 小さく、処理時間は現行以下だからである。**ただし実測していない。**

## 5. 決めきれていない1点

**SenseVoice を採るかどうかを決めるには、あと2つの数字が要る。**


| 足りないもの               | なぜ要るか                                                                                        |
| -------------------- | -------------------------------------------------------------------------------------------- |
| **台本コーパスでの日本語の逐語採点** | S6 を実施したのは台本コーパスができる前で、**凍結コーパス25件の観察しかない**。現行との比較は「落ちていないように見える」までで、**数字になっていない**           |
| **相づち9件を出せるか**       | **Nemotron を落とした軸**である。相づちが評価軸だと分かったのは S8 で、S6 はそれより前に走っている。**SenseVoice がこの帯で何を出すかは測っていない** |


**この2つは、新しく何かを作る話ではない。** 台本コーパス・採点スクリプト（`scripts/score_script_corpus.py`）・無音で流す入口・コーパスを画面で切り替える仕組みは**すべて既にある**。
**人の手数はゼロで、音も出ない。** 既存の足場で1回流して採点するだけである。

### 測らずに決めるなら

**現行を維持するのが筋である。** 理由は、SenseVoice の利得（崩壊と節の脱落が直る）が**日本語の相づちを失うリスクと釣り合うかを判断できない**ためで、**Nemotron はまさにそこで落ちた**。

**逆に言えば、この2つさえ通れば採用に踏み切る材料は揃っている。**

## 6. 採らない案（v3 から、実測で理由が強くなったもの）


| 案                            | 理由                                                              |
| ---------------------------- | --------------------------------------------------------------- |
| クラウド ASR                     | 費用と通信量。前提として除外                                                  |
| 二段階認識・別LLMによる整文              | 表示済みテキストの書き換え、2モデル、電力。**加えて、消えた節・消えた語頭はテキストからは復元できない**【実測で裏付いた】 |
| 言語別に複数の ASR を切り替える           | 「モデルは1つ」の前提に反する                                                 |
| 表記の置換辞書                      | **材料が2件で逆を向いている**【実測】。候補の7割は句読点で、これはモデル差し替えで消える                 |
| 前余白を足し戻す                     | `threshold` **のほうが軽く同じ問題に効く**【実測】。35秒ぶんの音（約2.2MB）を常時持ち越す代償が要らない |
| `minSpeechDuration` を下げる     | **逆効果**【実測】。区切りは増えるが中身が空で、`なるほど` が `どう` に化ける                    |
| `maxSpeechDuration` で長い発話を割る | **そういう設定ではない**【実測】。10.0秒にしても最長の区切りは 10秒に収まらない                   |
| master の未リリース実装を前提にした設計      | Nemotron の用語登録・ビームサーチは master にしか無い。**S9 は S7 が落ちたため実施していない**   |
| 雑音抑制を常時かける                   | **生活音・機器切替では取りこぼしが出なかった**【実測】。雑音が主因という診断が付かない                   |
| 充電中にまとめて認識する（録りだめ）           | 数時間の遅延は「即時性を譲る」とは別のUXになる                                        |

## 7. 条件が変わったら見直すもの

**追加の調査を積むためではなく、状況が変わったときに数え直すための一覧である。**


| 変わること                                | 見直すもの                                               |
| ------------------------------------ | --------------------------------------------------- |
| sherpa のリリース版に NeMo 用の用語登録・ビームサーチが入る | 現行モデルのまま課題①②に能動的な手が増える。S9 の条件が復活する                  |
| 端末の RAM が増える、または Qwen3 の軽量版が出る       | **課題②が解ける**。英字で出せることは実証済み                           |
| SenseVoice や Nemotron に替えた           | **置換辞書の候補を数え直す。** 候補の7割を占めていた句読点が消えるため、内訳が変わる       |
| 日本語の同じ表記ゆれが5件以上くり返す                  | 置換辞書を再検討する。数え方（`extract_notation_candidates.py`）はある |
| 正解テキスト側の表記を統一した                      | 同上。いまは `明日`/`あした`、`一番`/`いちばん` が混在していて寄せる先が無い        |
| 1日の電池を本気で詰める                         | 常時稼働側の 9.48% を削る。**モデル差し替えでは効かない**【推論】              |

## 8. 測り方についての教訓

**この一連の spike でいちばん再利用が効くのは、結論ではなく測り方である。**


| 教訓                                                                                                 | 出所                                                           |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| **切り出し済みの wav を VAD に通し直す経路は、本番より厳しい条件になる。** 語頭が 200ms 削れる（連続音では 30〜60ms）。**この経路だけで測ると効果を過大に見積もる** | S5 §7。`threshold` の +6.9pt も前余白の +6.7pt も、大半は測り方が作った損失の回復だった |
| **空の結果の件数は指標として弱い。** 件数が同じでも中身は入れ替わる。**空より悪い壊れ方（35秒 → 3文字）は件数に現れない**                               | S4                                                           |
| **数文字の差を「効果あり」と読まない。** 版を1つ上げるだけで25件中15件が数文字動く                                                     | S4                                                           |
| **カタカナ音写に文字一致率を当てない。** 内容ではなく表記の差を測ってしまう                                                           | S6・S8・`lead-padding` で繰り返し踏んだ                                |
| **コーパスに「効く帯」を含める。** 長い発話しかない集合では、前余白も `threshold` も何もしない                                           | `lead-padding` §6                                            |
| **ラベルはモデルの失敗を写す。** 現行が出せなかった音は `noise` に落ちていた。実際は本人の英語だった                                          | S3 §3                                                        |
| **逐次型を測るときは、末尾の無音をチャンク長以上にする。** 上流の例は参考であって仕様ではない                                                  | S8 §4                                                        |
| **「人が聴いて分かるか」を指標にしない。** 人の耳に語として聞こえる程度の欠けでも、モデルは語を落とす                                              | S2 §6                                                        |
| **比較の対応づけは、テキストの並びではなく区切りの開始位置で取る**                                                                | S5 §8。本人が「比較する文が違う？」と指摘した                                    |
