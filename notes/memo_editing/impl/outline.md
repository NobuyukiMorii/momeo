# 一覧の編集と修正の記録 実装計画

一覧を、ふつうのメモ帳のように自由に書き直せるようにする。本文のどこかをタップするとカーソルが立ってキーボードが出て、キーボードをしまうと編集が終わる。段落をつなげる・分ける・手で書き足すのも自由にする。

ここでの段落は、今のブロック（続けて話した発話のまとまり。DB では `VoiceMemos` の1行）と同じもの。1つの段落が1つのブロックで、改行が段落の区切りになる。一覧はもともと全ブロックを1つの `UITextView` / `TextView` にしているので、それをそのまま書ける文書にする。

あわせて、「認識したままの文字列」と「直した後の文字列」を DB に残し始める。使い方は決めない（長い目で見れば、認識器へのヒント語や LLM への参考に使える）。段落はつながったり分かれたりするので、記録は段落に頼らない形で持つ。

今と変わること:

- 今は、一覧の本文は読むだけで、できるのは文字選択からの「コピー」と「削除」だけ。切り替えたあとは、タップや長押しで編集が始まり、キーボードで書き直せる。一覧の右下（キーボードのすぐ上）に本文に重ねて出す丸いボタン（iOS。キーボードをしまうアイコン）か、キーボードを下ろす操作で編集を終える
- 段落の頭でバックスペースを押すと、前の段落とつながる。段落の途中で改行すると、そこで2つに分かれる。声を使わずに、手で段落を書き足せる
- 今は、文字選択のメニューに momeo が足した「削除」がある。切り替えたあとは、ふつうのバックスペースやカットで消すので、この「削除」はなくなる
- 今は、認識した文字列はブロックの本文へつながれるだけで、追記や削除のたびに書き換わり、元の形が残らない。切り替えたあとは、認識した発話を1つずつ書き換えずに残す（発話の記録）
- 編集を終えるたびに、変わった段落の前後の文字列を残す（修正の記録）
- 開発用コンソールから、発話の記録と修正の記録を書き出せる

変わらないこと:

- 一覧の見た目（段落の間の余白、右の縦線、日付の区切りの横線、スクロールつまみ、発話中の「.」）
- コピー（段落をまたぐときは、間に空行を入れる）
- 声の入り方（続けて話した発話は、末尾の段落に区切りなしでつなぐ）。編集の間も録音は続ける
- 認識器への渡し方（ヒント語はまだ渡さない）

進め方:

- 1 step = 1 commit = 1つの目的
- 見出しに【iOS】【Android】【共通】を付ける
- どの step の後でもビルドが通り、録音できる状態を保つ。記録を残す仕組みを先に入れ（Phase 1）、編集を後から足す（Phase 2）。記録は後から足しても、それまでの分は戻らないため
- 各 step は `phaseN/stepNN_名前/` に置く（計画は `plan.md`。説明資料の HTML は、頼んだときだけ作る）
- Swift・Kotlin を変えた step は、`make run` し直して確かめる

---

## 全体の流れ

```text
Phase 1  記録を残し始める・並び順を持たせる（DB を変える）   ← 見た目は何も変わらない
  ↓
Phase 2  一覧を自由に書き直せるようにする                   ← 使い心地が変わるのはここだけ
  ↓
Phase 3  記録を取り出す・仕様書
```

## 編集の決まりごと

### 声と編集の関係

- 声はいつも文書の末尾に入る。末尾の段落につなぐか、新しい段落を起こすかのどちらか（今と同じ）
- 編集を始めた時点で、末尾の段落へのつなぎをやめる（`_endCurrentBlock`）。編集の間に話した発話は、末尾に新しい段落として出る
- 1文字ずつ表示している途中の段落は書き直せない。その段落の頭でバックスペースを押しても、前の段落とはつながらない
- 編集の間は、書き直している文書を Dart から届いた本文で置き換えない。Dart から届いたもののうち、末尾に増えた段落だけを足す

### 段落と DB の行の対応

ネイティブ側は、文書の各文字に「どの行（`VoiceMemos.id`）から来た文字か」の印を付けておく（iOS は `NSAttributedString` の属性、Android は span）。打った文字やペーストした文字は、カーソルの前の文字の印を引き継ぐ。編集を終えたら、段落ごとに「中身」と「含まれる印」を Dart へ渡し、Dart が DB の行に戻す。

| 編集の後の段落 | DB での扱い |
| --- | --- |
| 印が1つで、その行がまだ使われていない | その行の本文を書き換える |
| 印が2つ以上（段落をつなげた） | 一番古い行に本文をまとめ、ほかの行は消す |
| 印が、前の段落ですでに使われた行と同じ（段落を分けた） | 新しい行を足す。日時は元の行のものを引き継ぐ |
| 文字が無い（空の段落） | 保存しない |

どの段落にも出てこなくなった行は消す。

※ 日付の区切りの横線は、今と同じく段落の日時（`createdAt`）で引く。違う日の段落をつなげると、その境目の線は消える。

### 並び順

段落を分けると、同じ日時の行ができ、日時だけでは並びが決まらない。そこで、行に並び順（`position`）を持たせ、一覧は並び順で並べる。新しい発話の段落は末尾に足し、編集を終えたら、文書の順に並び順を振り直す。

## DB で変えるもの

`schemaVersion` を 1 から 2 に上げ、マイグレーション（`MigrationStrategy` の `onUpgrade`）で変える。今あるブロックはそのまま残る（その分の発話の記録は無い）。

段落（`VoiceMemos`）: 並び順の列を足す。

| 列 | 中身 |
| --- | --- |
| `position` | 並び順（小さいほど上）。足すときは、今ある行に日時の順で振る |

発話の記録（`Utterances`）: 認識した発話1つにつき1行。書いたら書き換えない。

| 列 | 中身 |
| --- | --- |
| `id` | 自動採番 |
| `content` | 認識したままの文字列（前後の空白だけ落としたもの） |
| `recognizedAt` | 確定した日時 |
| `durationSec` | 発話の長さ（秒。`SttTranscribed.durationSec`） |
| `memoId` | そのときつないだ段落の `id`（手がかり。段落はあとでつながったり消えたりするので、今もあるとは限らない） |

修正の記録（`MemoEdits`）: 1回の編集（始めてからキーボードをしまうまで）につき1行。

| 列 | 中身 |
| --- | --- |
| `id` | 自動採番 |
| `beforeText` | 編集の前の、変わった段落の文字列（複数の段落は改行でつなぐ） |
| `afterText` | 編集の後の、変わった段落の文字列（全部消したときは空） |
| `editedAt` | 編集を終えた日時 |

※ 「変わった段落」は、編集の前後の文書を段落ごとに比べ、先頭と末尾から同じ段落を除いた残り。カーソルの位置などは持たない。

※ 学習に使いたい「認識した文字列 → 最終的な文字列」の組は、発話の記録と今の本文（または修正の記録）を、日時と文字の近さで後から照らし合わせて取り出す。段落の `id` には頼らない。

※ 段落を消しても、発話の記録と修正の記録は消さない。消したもの自体が「いらない発話」の例になるため。全件削除（`deleteAll`）のときだけ、2つの記録も一緒に消す。← 決めどころ。消したら跡も残らない方が自然と感じるなら、段落を消したときに、その段落に関わる記録も消す

## Phase 1 記録を残し始める・並び順を持たせる

| step | やること |
| ---- | ------------------------------------------------------------ |
| 1    | 【共通】DB に並び順・発話の記録・修正の記録を足す |
| 2    | 【共通】確定した発話を、発話の記録に残す |

※ step 1 は `app_database.dart` に `position` と2つのテーブル、マイグレーションを足し、`app_database.g.dart` を作り直す。`voice_memo_repository.dart` では、`findAll` を並び順で並べ、`insert` で末尾の並び順を振り、記録の読み書き（`insertUtterance`・`insertEdit`）を足す。`deleteAll` で2つの記録も消す。

※ step 2 は `listening_providers.dart` の `_onTranscribed` で、`_startNewMemo`・`_appendToTarget` のあとに発話の記録を1行足す。画面を離れた後に届く末尾の発話も、段落と同じく保存する。

## Phase 2 一覧を自由に書き直せるようにする

| step | やること |
| ---- | ------------------------------------------------------------ |
| 3    | 【共通】編集の始まり・終わりを受け取り、段落を DB に戻して保存する |
| 4    | 【iOS】一覧の本文を書けるようにする |
| 5    | 【Android】一覧の本文を書けるようにする |

※ step 3 は Dart 側だけ。`native_memo_list.dart` に、ネイティブから届く `editingStarted`（編集が始まった）と `editingEnded`（終わった。段落ごとの中身と印の一覧）を足す。`listening_providers.dart` に `saveEditedDocument` を足し、「段落と DB の行の対応」の表どおりに行を書き換え・足し・消し、並び順を振り直し、修正の記録を1行足す。ここまでを1つのトランザクションにする。この step ではまだネイティブから呼ばれないので、動きは変わらない。

※ step 4 は `NativeMemoList.swift`。`isEditable` を `true` にし、書いている間だけ、一覧の右下（キーボードのすぐ上）に、キーボードをしまう丸いボタンを本文に重ねて出す（iPhone のキーボードには、しまうキーが無いため。`inputAccessoryView` にすると、その横に本文が出なくなるので使わない）。カーソルの高さは文字の高さに合わせる（`caretRect(for:)`）。文字の印は `MemoBlock.range` の代わりに属性で持ち、打った文字に印が付くよう `typingAttributes` に載せる。1文字ずつ表示している途中の段落への書き換えは、`textView(_:shouldChangeTextIn:replacementText:)` で断る。そのボタン・キーボードを下ろしたとき（`textViewDidEndEditing`）・背面に回ったときに `editingEnded` を送る。日付の区切りの横線と縦線は、書き換えのたびに位置を測り直す。メニューの「削除」（`deleteSelectedText`）と、選択を外すタップ（`MemoSelectionDismissTap`）は外す。

※ step 5 は `NativeMemoList.kt`。今の `TextView` は文字選択だけなので、`EditText` 相当にする。文字の印は span で持ち、書き換えを断るのは `InputFilter` で行う。メニューの「削除」を外す。iOS より変える量が多い。

※ step 4・5 で `deleteText` を送る側がなくなるので、step 5 のあとに Dart 側の `deleteTextRanges` と `onDeleteText` も消す（step 5 に含める）。

### Phase 3 に進む前に確かめること

| 確かめること | iOS | Android |
| --- | --- | --- |
| タップした位置にカーソルが立ち、キーボードが出るか | 未確認 | 未確認 |
| キーボードがカーソルの行を隠さないか（一覧が押し上がるか） | 未確認 | 未確認 |
| スクロールしようとして触れただけで、編集が始まってしまわないか | 未確認 | 未確認 |
| 段落をつなげる・分ける・手で書き足すと、保存の後も同じ並びで出るか | 未確認 | 未確認 |
| 編集の間に話しても、書き直している文書が崩れず、末尾に新しい段落が出るか | 未確認 | 未確認 |
| 日本語入力の変換中（未確定の文字）に、新しい段落が届いても崩れないか | 未確認 | 未確認 |
| しまうボタン・キーボードを下ろす・背面に回る、のどれでも保存されるか | 未確認 | 未確認 |

## Phase 3 記録を取り出す・仕様書

| step | やること |
| ---- | ------------------------------------------------------------ |
| 6    | 【共通】開発用コンソールから、発話の記録と修正の記録を書き出す |
| 7    | 【共通】仕様書を直す |

※ step 6 は、開発用コンソールの Diagnostics と同じく共有ボタンで JSON を渡す。中身は「発話の記録」「修正の記録」「今の本文（段落ごと、日時つき）」の3つ。Mac に送って LLM で眺め、どんな直しが多いかを見るために使う。

※ step 7 の対象は `notes/specs/listening_flow.md`（「文字選択」の節を編集の節に書き換え、「メモのまとめ方」に段落のつながり・分かれを、新しい節に2つの記録を足す）。仕様書は無時制で書く。

## この計画でやらないこと

- 修正の記録から言葉を拾い、認識器へヒント語として渡すこと（iOS の `SpeechTranscriber` の文脈の語句、Android の `EXTRA_BIASING_STRINGS`）。記録がたまってから、別の計画にする
- 発話の記録と本文の照らし合わせ（書き出した記録を Mac で眺めてから考える）
- LLM での自動の補正・要約
- 段落の並べ替え（ドラッグで動かすなど。カットとペーストで動かした文字は、ペースト先の段落の一部になる）
- 保存した後の取り消し（編集の間は OS の取り消しが効く）
