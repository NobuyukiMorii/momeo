# 本人の声の判定 — sherpa-onnx 調査

調査日: 2026-09-27。目的は、詳細仕様を決める前に機能・制約・実装の選択肢を理解すること。ここにある設計案と数値の候補は決定事項ではない。

## 現時点でわかったこと

- **現在の momeo に本人照合を追加する土台はある。** 使用中の `sherpa_onnx 1.13.8` の Dart API から特徴量抽出・登録・照合を呼べる。既存の16kHzモノラル音声と音声処理 isolate を利用できる。
- **「本人／他人／雑音」は一つのAPIでは完結しない。** 音声かどうかを調べるVAD、登録者との比較、判断保留を組み合わせる。照合で一致しない音が、直ちに他人の声だとは限らない。
- **初回に短い文章を複数読んでもらう案は実現可能。** 必要な秒数の一律の保証はない。公式の登録サンプル音声は話者ごとに合計約7〜10秒だった。以前提示した15〜30秒は検証開始用の提案であり、sherpa-onnxの要件ではない。
- **「使うほど精度が上がる」はアプリ側で作る機能。** 特徴量の自動更新、品質の選別、保存、更新履歴、誤更新からの回復はライブラリ任せにできない。
- **最多発話者と端末のユーザーは別の概念。** 会話相手・テレビ・会議の進行役が最多になる場合がある。初回登録を本人の基準として残し、発話量は補助情報として扱う案が有力。
- **VADの区切りと話者交代は一致しない。** 今のmomeoは無音1.5秒で区切るので、一つの区間に複数人が入る。区間全体の照合だけでは本人の言葉だけを取り出せない。

以上の根拠・リンクは各資料に記載。

## 調査の範囲と確度

**確認済み:** 公開ドキュメント、バージョン固定のC++ソース、ローカルのDartパッケージ、momeoのコード、公開Issueの本文とコメント、第三者実装のコード、公式WAVのヘッダー情報。

**未実施:** 本人・他人の録音での推論、iOS/Android実機の速度・消費電力・メモリ測定、モデルの精度比較、アプリ機能の実装。APIが存在することと、対象端末で十分な品質・速度になることは分けて判断する。
